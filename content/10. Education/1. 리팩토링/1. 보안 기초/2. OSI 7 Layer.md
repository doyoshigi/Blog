# OSI 7 Layer
## 1. OSI(Open Systems Inerconnection) Model)이란?
![[Pasted image 20251209204438.png]]

OSI 모델이란 국제 표준화 기구(ISO, International Standards Organization)에서 만든 국제 표준 모델입니다. OSI나 TCP/IP와 같은 모델이 없었을 때에는 네트워크 단말기를 만들 때 프로토콜을 독자적으로 설계했기 때문에 제조사가 다르면 서로 통신이 불가능 했었습니다.

하지만 OSI, TCP/IP 등과 같은 모델이 등장한 이후 제조사들이 모델로 단말기를 제작하기 시작하면서 상호 연결이 가능해졌습니다.

이렇게 OSI 모델처럼 프로토콜을 모아서 계층화 시켜놓은 것 **프로토콜 스택** 또는 **프로토콜 스위트**라고 합니다.

### 1.1 왜 OSI 모델이 중요한가?
**문제 해결에 사용**  
현재 더 단순한 인터넷 프로토콜을 사용하는 등 OSI모델이 엄격하게 지켜지지 않고 있음에도 네트워크 문제를 해결하는 데 유용하게 활용이 가능합니다. 문제를 분석할 때 OSI 모델을 참고하여 특정 계층의 문제로 범위를 좁혀 불필요한 작업을 줄일 수 있습니다.

**이해가 쉽다**  
복잡한 시스템을 설계할 때 이미 계층에 따라 분해하여 추상화하므로써 사람들의 이해를 도와줍니다.

또한 각 계층에 사용되는 프로토콜의 작업이 정의되어 있기 때문에 OSI모델에 따라 구현한 네트워크 시스템을 잘 이해할 수 있도록 돕습니다.

그리고 계층별로 추상화되어있기 때문에 모델의 세부 사항을 엔지니어가 파악하지 않아도 됩니다.

### 1.2 왜 계층으로 나누는가?
**유지보수가 용이**  
계층으로 나누어 모듈화하면 시스템의 유지보수와 업데이트에 용이합니다. 예를 들어서 Transport Layer에 변경사항이 생겨 수정하려고 하면 계층마다 기능이 독립적으로 나뉘어져 있으므로 나머지 Layer는 수정하지 않고 Transport Layer만 수정하면 되기 때문입니다.

**복잡한 시스템을 이야기, 디자인 할 때 용이**  
복잡한 시스템을 이야기할 때에는 그 시스템을 정확히 파악하는 것이 중요합니다. 계층으로 추상화 하는 것은 이해를 쉽게 만들어 1.1에서 언급한 것처럼 문제를 해결할 때나 새로운 시스템을 디자인할 때 가이드를 제공해 좀 더 효과적으로 문제를 해결할 수 있도록 합니다.

## 2. 7계층
![[Pasted image 20251209204747.png]]

OSI 모델의 계층은 5~7 계층인 상위 계층, 1~4 계층인 하위 계층으로 총 7개의 계층으로 구성되어 있습니다.

### 7 - 애플이케이션 계층
![[Pasted image 20251209204803.png]]

애플리케이션 계층은 가장 상위 계층으로 사용자의 데이터와 직접 상호작용하는 유일한 계층이며 애플리케이션이 어떻게 통신하는지 규정합니다.

여기서 웹 브라우저, 이메일 클라이언트와 같은 애플리케이션은 이 계층을 통해 통신을 개시합니다.(이러한 애플리케이션은 계층의 일부가 아님)

애플리케이션 계층 프로토콜은 웹용 프로토콜인 HTTP, 이메일 통신 프로토콜인 STMP, 원격 로그인 프로토콜인 SSH 등이 있습니다.

### 6 - 프레젠테이션 계층
![[Pasted image 20251209204819.png]]

프레젠테이션 계층은 애플리케이션 계층이 데이터를 사용할 수 있도록 준비하는 역할을 합니다.  
데이터 변환, 암호화, 압축을 담당합니다. (데이터 형식과 관련된 것) 

**데이터 변환**  
서로 통신하는 애플리케이션이나 장치가 인코딩하는 방법이 다를 수 있으므로 이를 수신 장치의 애플리케이션 계층이 사용하는 방식으로 데이터를 변환합니다.

**암호화**  
장치가 암호화된 연결을 통해 통신하는 경우, 계층 6은 최종 송신자가 전송하는 데이터를 암호화하여 전송하고 최종 수신자에게 암호화를 디코딩하여 애플리케이션 계층에 제시합니다.

**압축**  
5 계층에 전송하기전에 압축하여 전송합니다. 이는 통신의 속도와 효율에 도움을 줄 수 있습니다.

### 5 - 세션 계층
![[Pasted image 20251209204839.png]]

세션 계층은 두 기기 사이의 통신을 시작하고 종료하는 일을 담당하는 계층입니다.  
세션이란 통신이 시작될 때부터 종료될 때까지의 시간을 세션이라고 합니다.

세션 계층은 교환되고 있는 모든 데이터가 전송될 수 있도록 충분히 오랫동안 세션을 개방한 다음 리소스를 낭비하지 않기 위해서 세션을 즉시 닫을 수 있도록 보장합니다.

그리고 세션 계층은 체크포인트를 사용할 수 있습니다. 예를들어서 10MB파일이 전송될 때 세션 계층이 2MB마다 체크 포인트를 설정하면 5MB가 전송된 후 연결이나 파일에 문제가 생기면 마지막 체크 포인트(4MB구간부터)에서 세션을 다시 시작하는 것이 가능합니다. 이렇게 되면 파일을 처음부터 다시 전송할 필요 없이 4MB구간 이후부터 전송하면 됩니다.

### 4 - 전송 계층
![[Pasted image 20251209204851.png]]

전송 계층에서는 두 기기 간의 EndToEnd 통신을 담당합니다. 포트를 할당하며 종단 간 통신의 신뢰성을 제공하기 위해 데이터가 제대로 도달하도록 커넥션 설정, 오류 제어 등을 수행합니다.

세션 계층에서 데이터를 가져와 네트워크 계층으로 보내기 전에 세그먼트(segment)라고 하는 조각으로 분할합니다.  
수신을 할 때에는 전송 계층에서 세션 계층이 이용할 수 있는 데이터로 다시 재조립해야합니다.

전송 계층은 흐름 제어 및 오류 제어의 기능도 합니다.

**흐름 제어**  
연결 속도가 빠른 송신자가 연결 속도가 느린 수신자를 압도하지 않도록 최적의 전송 속도를 설정합니다.

**오류 제어**  
데이터가 모두 수신되었는지 확인하고 수신되지 않은 경우 재전송을 요청하여 최종 수신자에 대해 오류 제어를 수행합니다.

전송 계층 프로토콜로는 전송 제어 프로토콜인 TCP, 사용자 데이터그램 프로토콜인 UDP 프로토콜이 있습니다.

### 3 - 네트워크 계층
![[Pasted image 20251209204915.png]]

네트워크 계층은 서로 다른 두 네트워크 간 데이터 전송을 담당합니다. 네트워크 상의 주소를 정의하고 통신할 목적지까지의 경로를 선택합니다.  
같은 네트워크 안에서 통신하는 경우 네트워크 계층이 필요하지 않습니다.

네트워크 계층은 전송 계층에서 받은 세그먼트를 더 작은 단위인 패킷으로 나누어 전송합니다. 수신할 때에는 패킷을 다시 합쳐서 전송 계층에서 사용할 수 있는 데이터로 합쳐야 합니다.

네트워크 계층은 데이터가 목적지에 도달하기 위한 최적의 물리적인 경로를 찾는데 이를 **라우팅**이라고 합니다.

네트워크 계층 프로토콜로는 IP, 인터넷 제어 메시지 프로토콜인 ICMP 등의 프로토콜이 있습니다.

### 2 - 데이터 링크 계층
![[Pasted image 20251209204933.png]]

데이터 연결 계층은 동일한 네트워크 내에 있는(물리적으로 직접 연결된) 장치 간 데이터 전송을 담당합니다.

네트워크 계층에서 패킷을 가져와 프레임이라고 불리는 더 작은 데이터로 나눕니다. 네트워크 계층과 마찬가지로 데이터 연결 계층도 인트라 네트워크 통신에서 흐름 제어 및 오류 제어를 담당합니다.(전송 계층은 네트워크 간 통신에 대해서 흐름 및 오류 제어 담당)

### 1 - 물리 계층
![[Pasted image 20251209204945.png]]

물리 계층에는 케이블, 스위치 등 데이터를 물리적으로 전송하는 장비가 포함됩니다.

물리 계층에서는 데이터 링크 계층에서 받은 프레임을 비트 스트림으로 변환하여 전기 신호나 광신호로 장비를 통해서 데이터를 전송합니다.

같은 방식으로 장비를 통해 수신한 신호를 변환하여 데이터 링크 계층으로 보내줍니다.

### 다른 모델들
**DoD 모델**
![[Pasted image 20251209205009.png]]

비슷한 모델로는 미국 국방성에서 제시한 DoD 모델이 있습니다.

DoD모델과 OSI모델을 비교하면 OSI모델의 Application, Presentation, Session 계층이 Aplication 계층으로, Data Link, Physical 계층이 Network 계층으로 포함된 **Application, Transport, Internet, Network 계층**으로 이루어져 있습니다.

![[Pasted image 20251209205020.png]]

더 유명한 말로 **TCP/IP 모델**이라고 합니다.

## 3. 데이터 송수신
![[Pasted image 20251209205040.png]]

그렇다면 이러한 네트워크 스택을 통해서 어떻게 데이터가 전송될까요?

DB에 데이터가 저장되어 있는 캘린더에 새로운 일정을 등록한다고 가정해 보겠습니다.

사용자가 캘린더에 새로운 일정을 등록하겠다는 요청과 그 데이터를 캘린더 회사의 DBMS에게 보내야 사용자의 일정이 DB에 제대로 등록이 되겠죠.

DBMS로 사용자의 요청과 데이터를 송신할 때에는 상위 계층에서 부터 하위 계층까지 순서대로 데이터를 처리하여 내보냅니다.

예를 들어서 application 계층에서 transport 계층으로 데이터전달하고  
transport 계층은 포트를 할당하여 network계층으로 전달합니다.  
network 계층에서는 라우팅을 하여 최선의 전송 경로를 지정하고 그에 관한 정보를 추가합니다.  
그리고 network 계층의 packet을 전달받은 Link 계층은 같은 네트워크 내에 존재하는 노드 경로를 찾아 그 정보를 추가하고  
마지막으로 physical 계층에서 물리적인 신호로 변환되어 전달되게 됩니다.

이때 각 계층에서 필요한 정보(**헤더**)를 상위 계층에서 전달받은 데이터에 추가하게 되는데 이를 **캡슐화**라고 합니다.

반대로 데이터를 수신할 때에는 하위 계층에서 상위 계층으로 데이터를 처리하여 목적지로 전달합니다.  
캡슐화 과정에서 추가된 정보를 각 계층에서 확인하고 헤더를 제거하여 상위 계층으로 보내는데 이를 **역캡슐화**라고 합니다.
