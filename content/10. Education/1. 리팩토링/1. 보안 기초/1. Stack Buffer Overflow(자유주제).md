백악관의 ONCD(국가사이버책임자실)에서 2024년 2월 26일에 보고서를 발표하여 메모리 안전 취약성이 없는 프로그래밍 언어를 사용해 사이버 공격의 위험을 줄여야 한다고 했었습니다. 이 보고서를 보고 많은 유튜브에서 c언어를 이제 그만사용해야 한다고 다뤘었는데요. 거기에서 C언어와 C++의 대표적인 보안 취약점인 BOF가 생각나서 이 주제를 선정하게 되었습니다.

## 0. Overflow 취약점
![[Pasted image 20251209202302.png]]

CVE에 등록된 데이터를 살펴보면 overflow 취약점은 2024년을 기준으로 19604건으로 전체에서 3위를 차지할 정도로 많은 취약점이 존재하는 부분입니다.

## 1. Stack Overflow VS Stack Buffer Overflow
- **Stack Overflow** : 스택 영역은 실행중에 크기가 동적으로 확장될 수 있습니다. 하지만 메모리의 크기는 한정되어 있으므로 스택이 무한히 확장될 수는 없습니다. Stack Overflow는 스택 영역이 너무 많이 확장되어 발생하는 버그를 의미합니다.
- **Stack Buffer Overflow** : Stack Buffer Overflow는 스택에 위치한 버퍼의 크기보다 많은 데이터가 입력되어 발생하는 버그를 의미합니다.

용어가 비슷하지만 의미가 전혀 다르므로 주의하여 사용해야 합니다.

## 2. 스택 버퍼 오버플로우(Stack Buffer Overflow)
스택 버퍼 오버플로우는 스택의 버퍼에서 발생하는 오버플로우를 말합니다. 이를 이해하기 위해서는 버퍼와 오버플로우의 개념을 이해해야 합니다.

### 2.1 버퍼(Buffer)
버퍼(Buffer)라는 단어는 일상에서 '완충 장치'라는 뜻으로 사용되며 컴퓨터 과학에서는 '데이터가 목적지로 이동되기 전에 보관되는 임시 저장소'라는 뜻으로 사용됩니다.

버퍼는 데이터의 처리속도가 다른 두 장치가 있을 때, 이 둘 사이에 오가는 데이터를 임시로 저장해두어 처리속도가 다름에서 발생하는 문제를 해결합니다.

![[Pasted image 20251209202408.png]]

예를들어 한번에 10글자씩 쓸 수 있는 키보드와 한번에 5 글자씩 읽을 수 있는 컴퓨터가 존재한다고 가정해보겠습니다

![[Pasted image 20251209202420.png]]

만약 버퍼가 없는 상태에서 키보드가 바로 컴퓨터로 "1234567890"을 입력했습니다.

하지만 컴퓨터는 한 번에 5글자밖에 읽지 못하기 때문에 컴퓨터는 "12345"까지만 읽고 뒤에 있는 "67890"는 유실되겠죠.

![[Pasted image 20251209202429.png]]

하지만 여기서 중간에 버퍼를 두어 키보드가 버퍼에 10글자씩 입력하게 하고 컴퓨터가 자신의 속도에 맞게 저장된 데이터를 버퍼에서 읽어가게 한다면? 유실되는 데이터 없이 잘 작동하게 됩니다.

버퍼가 유실될 뻔한 데이터를 저장하고 있었기 때문에 버퍼가 없었을 때에는 유실되었던 데이터가 이제는 유실되지 않게 된 것입니다.

이처럼 버퍼는 데이터가 안정적으로 목적지에 도달할 수 있도록 완충 작용을 하게 됩니다.

하지만 요즘에는 이런 완충의 의미가 많이 희석되어 데이터가 저장될 수 있는 모든 단위를 버퍼라고 부르기도 합니다. 예를 들어 스택에 있는 지역 변수는 '스택 버퍼', 힙에 할당된 메모리 영역은 '힙 버퍼'라고 부릅니다.

**버퍼링이란?** : 버퍼에서 유래된 단어로, 송신 측의 전송 속도가 느려서 수신 측의 버퍼가 채워질 때까지 대기하는 것을 의미합니다.

- 만약 키보드가 1초에 1글자씩 쓸 수 있고 컴퓨터는 효율을 위해 버퍼에 최소 5글자가 채워질 때까지 기다렸다가 한 번에 5글자씩 읽는다면 컴퓨터는 데이터를 읽기 위해서 5초의 버퍼링을 기다려야 하는 것이죠.

### 2.2 버퍼 오버플로우(Buffer Overflow)
버퍼 오버플로우는 문자 그대로 버퍼가 넘치는 것을 말합니다. 버퍼의 크기는 각각 다른데 `int`타입의 지역 변수는 4바이트, `char`타입에 길이가 `char`가 10개 저장될 수 있는 배열은 10바이트입니다.

버퍼 오버플로우는 버퍼의 크기보다 더 큰 크기의 데이터를 버퍼에 저장하려고 할 때 발생합니다. 크기가 10바이트인 배열에 20바이트짜리 데이터를 저장하려고할때 말이죠. 1L짜리 물통에 1.5L를 담으려고 하면 물이 넘쳐버리는 것과 같은 원리입니다.

![[Pasted image 20251209202504.png]]

위의 그림처럼 8byte 길이의 char 배열 A가 있습니다. 만약 A에 9byte 크기의 "excessive" 문자열을 저장하면 원래 저장하려고 했던 A의 범위를 벗어나서 A의 다음 메모리인 B까지 침범해버립니다.

일반적으로 버퍼는 메모리상에 연속해서 할당되어 있으므로, 어떤 버퍼에서 오버플로우가 발생하면, 뒤에 있는 값이 조작될 위험이 있습니다. 일반적으로 버퍼 오버플로우는 어떤 메모리 영역에서 발생하도 큰 보안 위협으로 이어집니다.

![[Pasted image 20251209202513.png]]

## 3. 버퍼 오버플로우 공격 예시
### 3.1 중요 데이터 변조
버퍼 오버플로우가 발생하는 버퍼 뒤에 중요한 데이터가 있다면, 해당 데이터가 변조됨으로써 문제가 발생할 수 있습니다.  
예를 들어 입력 데이터에서 악성 데이터를 감지하는 프로그램이 있을 때 공격자가 버퍼 오버플로우를 이용하여 악성 데이터 감지에 필요한 조건을 변경하여 악성 데이터가 존재함에도 프로그램이 감지하지 못하게 할 수 있습니다.

```C
// Name: sbof_auth.c 
// Compile: gcc -o sbof_auth sbof_auth.c -fno-stack-protector 
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int check_auth(char *password) { 
	int auth = 0;
	char temp[16];

	strncpy(temp, password, strlen(password));
	
	if(!strcmp(temp, "SECRET_PASSWORD"))
		auth = 1;
		
	return auth;
} 

int main(int argc, char *argv[]) {
	if (argc != 2) {
		printf("Usage: ./sbof_auth ADMIN_PASSWORD\n");
		exit(-1);
	}
	
	if (check_auth(argv[1]))
		printf("Hello Admin!\n");
	else 
		printf("Access Denied!\n");
}
```
위의 코드는 `main`함수에서 `check_auth`함수로 `argv[1]`을 전달하여 반환된 값이 0이 아니면 "Hello Admin!", 0이면 "Access Denied!"를 출력합니다.

`check_auth`함수에서는 16바이트 크기의 `temp`버퍼에 `password`를 복사하여 저장하고, 이를 "SECRET_PASSWORD"와 비교하여 같다면 1을, 다르다면 0을 `auth`에 저장하여 반환합니다.

여기서 `strncpy`함수를 통해 `temp`버퍼에 `password`를 복사할 때 `password`의 크기가 16바이트보다 더 클 경우 16바이트인 `temp`버퍼에 크기보다 더 큰 문자열이 복사되버립니다. 즉 스택 버퍼 오버플로우가 발생합니다.

`auth`는 `temp`버퍼 뒤에 존재하므로, `temp`버퍼에 오버플로우가 발생하면 `auth`의 값을 0이 아닌 임이의 값으로 변경시킬 수 있습니다.

이와같은 경우에는 실제 문자열이 동일한지의 여부와 관계없이 `check_auth`의 리턴값을 조작할 수 있습니다.

### 3.2 데이터 유출
C 언어에서 정상적인 문자열은 널 바이트로 종결되며 표준 문자열 출력 함수들은 이를 통해 문자열의 끝을 인식하고 어디까지 문자열을 출력할지 결정합니다.

만약 어떤 버퍼에 오버플로우를 발생시켜서 그 버퍼와 뒤에 따라오는 버퍼 사이의 널 바이트를 모두 제거하게되면 해당 버퍼를 출력시켜 다른 버퍼의 데이터도 같이 출력시키는 것이 가능합니다.

그렇게 획득한 데이터는 각종 보호기법을 우회하는데 사용될 수 있으며, 해당 데이터 자체가 중요한 정보일 수도 있습니다.

```C
// Name: sbof_leak.c
// Compile: gcc -o sbof_leak sbof_leak.c -fno-stack-protector
#include <stdio.h>
#include <string.h>
#include <unistd.h>
int main() {
	char secret[16] = "secret message";
	char barrier[4] = {};
	char name[8] = {};
	memset(barrier, 0, 4);
	printf("Your name: ");
	read(0, name, 12);
	printf("Your name is %s.", name);
}
```
위 코드는 8바이트 크기의 name버퍼에 12바이트의 입력을 받게되면 name버퍼 바로 다음에 이어지는 null 캐릭터로 이루어진 barrier버퍼의 값이 name버퍼에서 발생한 버퍼 오버플로우에 의해 사라지면서 barrier버퍼 다음에 오는 secret버퍼의 값을 읽을 수 있습니다.

### 3.3 실행 흐름 조작
프로그램은 함수를 호출할 때 반환 주소를 스택에 쌓고, 함수에서 반환될 때 이를 다시 꺼내서 원래의 실행 흐름으로 돌아갑니다. 이때 공격자가 스택 버퍼 오버플로우로 Return address를 조작하게 되면 기존에 실행흐름으로 돌아가는 것이 아니라. 공격자가 원하는 흐름으로 이동하게 만들 수 있습니다.

```C
// Name: sbof_ret_overwrite.c
// Compile: gcc -o sbof_ret_overwrite sbof_ret_overwrite.c -fno-stack-protector
#include <stdio.h>
#include <unistd.h>
void win() {
	printf("You won!\n");
} 

int main(void) {
	char buf[8];
	printf("Overwrite return address with %p:\n", &win);
	read(0, buf, 32);
	return 0;
}
```
이 코드에서는 win()의 주소를 출력하고, 8바이트 버퍼 buf에 32바이트 입력을 받습니다. buf이후에는 rbp 값과 반환주소 8바이트가 있기 때문에 16바이트를 입력한 후 win()의 주소를 입력하면 main함수가 끝날 때 win()이 호출되게 할 수 있습니다.

#### 실습
위의 실습과 마찬가지로 윈도우, 맥 환경에서 제대로 동작하지 않았습니다. 이 두 환경에서는 오버플로우를 감지하면 프로그램을 중단시키기 때문에 다음에는 가상머신 환경에서 테스트해봐야겠습니다.
