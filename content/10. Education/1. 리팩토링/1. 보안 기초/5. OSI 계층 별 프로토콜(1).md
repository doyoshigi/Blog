# OSI 계층 별 프로토콜(1)
![[Pasted image 20251209213623.png]]

OSI 7 Layer의 각 계층별 프로토콜을 설명하겠습니다.

## 1. Application Layer
### HTTP(HyperText Transfer Protocol)
World Wide Web(WWW) 상에서 정보를 주고 받을 수 있는 프로토콜입니다.  
주로 HTML 문서를 주고 받는데 사용하며 TCP와 UDP를 사용하고 80번 포트를 사용합니다.

### STMP(Simple Mail Transfer Protocol)
![[Pasted image 20251209213713.png]]

인터넷에서 이메일을 주고받기 위해서 사용되는 프로토콜입니다. TCP를 사용하며 25번 포트를 사용합니다.

유저 A가 유저 B에게 메일을 전송할 때 메일은 바로 그 유저의 컴퓨터로 이동하는 것이 아니라 중간에 메일 서버를 거치게 됩니다. 메일은 메일서버에 보관되고 다시 중간에 거쳐야 하는 메일서버로 보내지는 과정을 통해 A에서부터 B로 전달되게 됩니다.

SMTP는 이러한 과정에서 메일 서버간 송수신, 메일 클라이언트에서 메일서버로 메일을 보낼때 사용됩니다.

### POP3(Post Office Protocol)
**받는 메일**이라고 불리는 POP 서버(version3) 이메일을 받아오는 표준 프로토콜입니다. 110번 TCP 포트 번호를 사용합니다.

메일 서버에서 로컬 PC로 메일을 수신받을 수 있는 client/server 프로토콜입니다. 메일 서버에 저장되어 있는 메일을 로컬 pc로 가져오는 역할을 담당합니다.

pop3는 서버에서 메일을 받아오는 즉시 삭제되도록 만들어 졌지만 서버에 저장하게 설정도 가능합니다. 서버 스토리지 용량에 제한이 있는 경우 유리합니다.

### IMAP(Inernet Message Access Protocol)
POP와 같이 메일 서버 종류 중 하나입니다. 143번 TCP 포트 번호를 사용합니다.

POP와 달리 중앙 서버에 동기화가 이뤄지기 때문에 모든 장치에서 동일한 이메일 폴더를 확인할 수 있습니다.

서버에 이메일이 남겨진 상태로 사용자에게 이메일을 보여줍니다. 그렇기에 사용자는 언제 어디서나 원하는 메일을 열람할 수 있습니다.

메일이 서버에 저장되어 있기 때문에 로컬 PC에 문제가 생겨도 이메일에는 아무 영향을 미치지 않습니다.

### SMTP, POP3, IMAP
**SMTP와 POP3, IMAP의 차이점**  
SMTP는 메일 서버 간 전송규약이고 POP3와 IMAP는 유저가 메일 서버에서 메일을 받기 위해서 사용하는 프로토콜입니다.

**POP3, IMAP의 차이점**

| **POP3**                       | **IMAP**               |
| ------------------------------ | ---------------------- |
| 메일 서버에서 로컬 장치로 메일을 다운로드 받는다.   | 메일 서버에서 동기화가 이루어짐      |
| 수신함(받은 메일)을 다운로드하여 조회 가능       | 수신함 뿐만아니라 모든 메일함 조회 가능 |
| 로컬 장치로 다운로드 시, 서버에서는 해당 이메일 삭제 | 서버에 이메일 실시간 존재         |
| 오프라인 지원                        | 온라인, 오프라인 모두 지원        |

### FTP(File Transfer Protocol)
컴퓨터 간 파일을 전송하는데 사용되는 프로토콜입니다. 데이터 전달에는 20번 포트를, 제어정보 전달에는 21번 포트를 사용합니다.

**FTP 서버**  
FTP서버란 파일을 한 장치에서 다른 장치로 전송하는 소프트웨어 어플리케이션을 말합니다. 간단히 말해 FTP 서버는 FTP 주소를 가진 FTP 연결을 수신하는 데 사용되는 컴퓨터입니다.

FTP 서버는 받기와 보내기를 수행합니다. 사용자는 FTP 서버로부터 파일을 받을 수 있고 FTP 서버  
로 파일을 보낼 수도 있습니다. 파일을 업로드하면 업로드된 파일이 개인용 장치에서 서버로 전송되고 파일을 다운로드하면 다운로드된 파일이 서버에서 개인용 장치로 전송되죠. 따라서 기본적인 관점에서 보면 FTP 서버는 수신자와 전송자 사이에 위치한 중간 지점과도 같습니다.

클라이언트가 파일을 요청하면 서버가 요청된 파일을 제공하는 클라이언트/서버 프로토콜입니다. FTP프로토콜 연결을 설정하려면 두 개의 기본 채널이 필요한데 이를 **제어채널**과 **데이터채널**이라고 합니다.

**제어 채널**은 명령을 시작해 어떤 파일에 액세스할 것인지 등과 같은 기본 정보를 전달하는 채널입니다.  
**데이터 채널**은 두 장치 간에 파일 데이터를 전송하는 채널입니다.

연결을 설정하려면 사용자가 FTP 서버 로그인 정보를 제공해야 하는데 일반적으로 21번 포트를 기본 통신 모드로 사용하게 됩니다. 여기서 포트란 네트워크를 통한 정보 트랜잭션을 식별하는 데 사용되는 번호를 말합니다.

FTP의 연결 모드는 **능동 모드**와 **수동 모드**가 있습니다.

**능동 FTP 모드**에서는 서버가 데이터 요청을 승인하는 능동적인 역할을 합니다. 하지만 능동 모드에서는 방화벽으로 인한 문제가 종종 발생합니다. 제삼자가 권한이 없는 섹션에 엑세스하려고 하면 해당 세션이 차단되는 것이죠.  
**수동 모드**에서는 서버가 능동적으로 연결을 유지하지 않습니다. 즉, 사용자가 데이터 채널과 명령 채널 모두를 설정하죠. 서버는 기본적으로 듣기만할 뿐, 능동적으로 관여하지 않음으로써 다른 장치가 대부분의 작업을 처리하도록 합니다.

**FTP가 유용하게 사용되는 경우**  
FTP는 주로 대량의 파일을 처리할 때 사용됩니다. 그래서 웹 개발에 특히 유용하죠. 웹사이트를 수정할 때 FTP 세션을 통해 파일 전송을 관리하면 특정한 파일 업로드, 이미지 파일 추가, 웹 템플릿 이동 등의 작업을 수월하게 처리할 수 있습니다.

FTP를 통해 폐쇄형 시스템 내에서 대량의 서버 배치 파일을 간단하게 전송할 수도 있습니다.

**장점**  
FTP의 가장 큰 장점은 동시에 여러 파일을 전송하고, 연결이 끊긴 경우 전송을 재개할 수 있으며, 전송 일정을 예약할 수 있다는 것입니다. 또한 오랫동안 사용되어 왔기에 대부분의 사람들이 이미 이 프로토콜에 익숙하다는 점도 있습니다.

**단점**
가장 치명적인 단점은 보안에 취약하다는 점입니다. 1970년대에 개발된 FTP는 현재 우리가 사용하는 대부분의 사이버 보안 조치보다 먼저 개발되었습니다. 또한 보안 프로토콜로 설계된 것이 아니기 때문에 FTP 전송은 암호화되지 않습니다. 그래서 데이터 패킷을 캡처하려는 해커들이 패킷 캡처 공격을 통해 비교적 쉽게 민감한 데이터를 읽을 수 있습니다.

**SFTP** 
따라서 위와같이 보안에 취약한 FTP대신 시큐어 셸(SSH) 데이터 스트림을 통해 높은 수준의 파일 보호가 가능한 프로토콜인 SFTP(SSH File Transport Protocol)를 사용하는 것이 좋습니다.  
21번 포트를 사용하는 FTP 클라이언트와는 달리 SFTP는 22번 포트를 사용합니다.

### TELNET(Teletype network)
로컬 영역이나 인터넷에 있는 원격 시스템의 가상 터미널을 제공하는 클라이언트 서버 프로토콜입니다.  
현재는 보안문제로 사용이 감소하고 있으며 원격 제어를 위해 SSH로 대체하는 추세입니다.

## 2. Presentation Layer
### SSL(Secure Socket Layer)
네트워크 레이어의 암호화 방식으로 HTTP, NNTP, FTP 등에 프로토콜에 사용됩니다.  
인증, 암호화, 무결성 보장을 수행합니다.

### ASCII(American Standard Code for Information Interchange)
문자를 사용하는 많은 장치에서 사용되며, 대부분의 문자 인코딩이 아스키에 기반합니다.  
하나의 문자는 7비트로 인코딩되며 33개의 출력 불가능한 제어 문자들과 공백을 비롯하여 95개의 출력 가능한 문자를 표현할 수 있습니다.

## 3. Session Layer
### Net BIOS
네트워크의 기본적인 입출력을 정의한 프로토콜입니다.

### RPC(Remote Procedure Call)
Windows 운영 체제에서 사용하는 원격 프로시저 호출 프로토콜입니다.

### WinSock(Windows Socket)
유닉스 등에서 TCP/IP 통신 시 사용하는 Socket을 Windows에서 그대로 구현한 프로토콜입니다.

## 4. Transport Layer
### TCP(Transmission Control Protocol)
전송제어 프로토콜로 네트워크의 정보 전달을 통제하는 프로토콜입니다. 데이터의 전달을 보증하고 보낸 순서대로 받게 해줍니다.  
Handshaking을 통한 신뢰성있는 데이터 전송이 가능합니다.

### UDP(User Datagram Protocol)
비연결성이고 신뢰성이 없으며 순서화되지 않은 Datagram 전송 서비스를 제공합니다.

## 5. Network Layer
### IP(Internet Protocol)
패킷 교환 네트워크에서 정보를 주고받는데 사용하는 정보 위주의 프로토콜입니다.  
호스트의 주소지정과 패킷 분할 및 조립 기능을 담당합니다.

### ICMP(Internet Control Message Protocol)
IP 프로토콜은 Best Effort 프로토콜이기에 IP 패킷 전송 중 에러가 발생하는 것을 감지할 수 없습니다.  
ICMP는 IP패킷에 포함되어 **에러 발생 원인** 및 **네트워크 상태**를 진단하고 원인을 파악을 해줍니다.

**기능**
1. Echo Request/Echo Reply
    - 호스트간 연결 테스트에 사용
2. Destination Unreachable
    - 목적지 도달 불가능 메시지
3. Time Exceeded
    - TTL 만료
4. ICMP Redirect
    - 패킷을 목적지에 보내기 위해 새로운 경로로 redirection
5. 오류 보고 및 상태 알림
    - 호스트, 라우터, 네트워크 등의 상태를 감지하고 다른 장비에게 보고
6. 네트워크 경로 추적
    - Traceroute/Tracepath

## 6. Data Link Layer
### Ethernet
LAN 구현 방식을 말하며 비연결성(connectionless)모드로 전송속도가 10Mbps 이상입니다.

### HDLC(High Level Data Link Control)
고속 데이터 전송에 적합하고, 비트 전송을 기본으로 하는 범용의 데이터 링크 전송제어절차입니다.

### PPP(Point to Point Protocol)
전화선 처럼 양단간 비동기 직렬 링크를 사용하는 두 컴퓨터 간의 통신을 지원하는 프로토콜입니다.

## 7. Physical Layer
### RS-232
보통 15m 이하 단거리에서 38400bps까지 전송을 위한 직렬 인터페이스 입니다.

### X.25/X.21
X.25는 패킷 교환망, X.21은 회선 교환망에 대한 액세스 표준입니다.
