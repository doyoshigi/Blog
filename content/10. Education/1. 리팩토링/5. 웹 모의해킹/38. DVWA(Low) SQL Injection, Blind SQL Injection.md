## SQL Injection
### SQL Injection이란?
![[Pasted image 20251212212954.png]]

웹 애플리케이션에서 사용자 입력값을 적절히 검증하지 않고 SQL 쿼리에 직접 삽입할 수 있는 공격입니다.

공격자는 입력 폼, URL 등의 경로로 악의적인 SQL 구문을 삽입하여 데이터베이스를 조작하거나, 민감한 정보를 탈취할 수 있습니다.

`2' ORDER BY [숫자]#`를 입력하여 컬럼에 따라 정렬을 시도했습니다.

- 이때 `#`은 주석을 나타내는 문자로 현재 파악된 SQL 구문에서 ORDER BY를 추가하기 위해 사용합니다.
- `SELECT firstname, surname FROM users WHERE id = '2' ORDER BY 1#';`(#이후 주석처리)

먼저 DB 목록을 확인하기 위해서 시스템 카탈로그인 information_schema를 조회해보았습니다.

`' UNION SELECT schema_name, 1 FROM information_schema.schemata#`

`' UNION SELECT table_name, 1 FROM information_schema.tables WHERE table_schema='dvwa'#`

조회 결과 guestbook, users 테이블이 존재하는 것을 확인할 수 있습니다.

유저의 정보가 담겨있을 것 같은 users 테이블을 조회해 보겠습니다. 

먼저 users 테이블의 컬럼 목록을 조회합니다. 입력창에 입력한 명령어는 아래와 같습니다.

`' UNION SELECT column_name, 2 FROM information_schema.columns WHERE table_schema='dvwa' and table_name='users'#`

`' UNION SELECT user, password FROM users#`

smithy의 비밀번호 해시값을 분석 사이트에서 확인해보니 MD5 또는 MD4 해시 함수를 사용한 것을 확인했습니다.

## 대응방안
- Prepared Statement를 사용하여 쿼리문을 미리 컴파일하고, 사용자의 입력은 변수로 전달하여 SQL 구문의 구조 변화를 차단합니다.
- 사용자의 입력값에 특수문자를 사용할 수 없도록 Regex나 화이트리스트 등을이용하여 필터링합니다.
- DB 계정에 필요한 권한만 최소한으로 부여하여 불필요한 읽기, 쓰기 권한을 제한합니다.

## Blind SQL Injection
### Blind SQL Injection 취약점이란?
Blind SQL Injection이란 참인 쿼리문과 거짓인 쿼리문 입력 시 반환되는 서버의 응답이 다른 것을 이용하여 이를 비교하여 데이터를 추출하는 공격입니다.

쿼리문의 결과값이 화면이나 에러 메시지로 드러나지 않는 환경에서 활용합니다.

Blind SQL Injection 공격에는 크게 2가지 종류가 있습니다.

#### **Boolean Based** Blind SQL Injection
SQL 쿼리가 참/거짓일 때 출력되는 페이지나 패킷의 차이가 있다면 사용합니다.

SQL 쿼리가 참이면 페이지가 정상 출력되거나 패킷의 길이가 달라지는 것을 이용하여 추론합니다.

**`' AND SUBSTRING((SELECT database()), 1,1)='a'--`**

위의 SQL문은 데이터베이스의 첫 글자를 잘라와서 'a'와 비교합니다.

첫 글자가 'a'라면 페이지가 정상 출력됩니다.

#### **Time Based** Blind SQL Injection
SQL 문이 참/거짓일 때의 차이가 존재하지 않는다면 결과에 따라 응답시간을 다르게 하여 참/거짓을 알 수 있습니다.

**`' AND IF(SUBSTRING((SELECT user()), 1,1)='r', SLEEP(5), 0)--`**

위의 SQL문은 현재 DB 사용자의 계정 이름의 첫 글자가 'r'이라면 SLEEP(5)가 실행되어 응답이 5초 늦게 오게 됩니다.

공격자는 응답이 느린 것을 보고 쿼리의 DB 계정의 첫 글자가 'r'임을 알 수 있습니다.

SQL Injection 실습과 다른 점은 이전에는 DB에서 조회한 레코드가 전부 아래에 출력되었지만 이제는 조건에 맞는 레코드가 존재하면 존재한다는 문구를, 존재하지 않는다면 존재하지 않는다는 문구를 출력합니다.

![[Pasted image 20251212214412.png]]

`' or '1'='1`, `' or '1'='2`를 입력한 결과 각각 존재, 존재하지 않음을 출력하는 것으로 보아 SQL Injection이 가능한 입력창임을 알 수 있습니다.

이제 이 출력문을 이용하여 내부 정보를 유추할 수 있습니다.

**Column 수**
`' UNION SELECT [숫자]#`를 입력하여 컬럼의 수를 알아낼 수 있습니다.

![[Pasted image 20251212214430.png]]

1 단독으로 입력하거나 1, 2, 3을 입력할 경우 오류가 나고 1, 2를 입력했을 때 존재한다고 출력되는 것으로 보아 내부 쿼리문의 컬럼이 2개라는 것을 알 수 있습니다.

**DB 이름 길이**
`2' AND length(database()) = [숫자]#`를 입력하여 DB 이름의 길이를 알아낼 수 있습니다.

![[Pasted image 20251212214440.png]]
![[Pasted image 20251212214446.png]]

숫자가 4일 때 참 문구가 출력되는 것으로 보아 DB 이름의 길이가 4인 것을 알 수 있습니다.

다음으로는 자동화 도구를 사용하여 SQL Injection을 시도해보겠습니다.

자동화 도구를 사용하는 이유는 쿼리 결과를 직접적으로 볼 수 없기에 수동으로 하나하나 결과를 보고 정리하기에는 시간이 너무 오래걸립니다. 따라서 자동으로 여러번 반복하여 결과를 출력해주는 자동화 도구를 사용하면 시간을 줄일 수 있습니다.

![[Pasted image 20251212214500.png]]

먼저 Burp Suite에서 Request 패킷의 쿠키값과 URL을 복사합니다.

복사한 값을 이용하여 인젝션 자동화/점검 도구인 SQLmap을 실행시킬 것입니다.

터미널에서 패킷에서 가져온 값들을 사용하여 SQLmap을 실행합니다. 명령어는 아래와 같습니다.

![[Pasted image 20251212214511.png]]

```
sqlmap --cookie "_ga_61TZV4HRGB=GS2.1.s1754468260$o1$g0$t1754468271$j49$l0$h0; _ga=GA1.1.1516584967.1754468260; PHPSESSID=73ef143f51c825c17a65473a588174cf; security=low; theme=light" –u "http://localhost/DVWA/vulnerabilities/sqli_blind/?id=1&Submit=Submit”–p id
```
위의 명령어는 페이지의 입력창에 입력하는 값에 어떤 취약점이 있는지를 테스트합니다.

### 대응방안
- SQL Injection의 대응방안인 Prepared Statement, 입력값 필터링, DB 계정 권한 최소화 등을 적용합니다.
- Boolean-based blind SQL Injection을 막기 위해 웹 사이트에서 쿼리의 참/거짓을 구분할 수 있는 정보(에러 메시지, 패킷의 길이 등)를 최소한으로 제공해야 합니다.
- Time-based blind SQL Injection을 막기 위해 쿼리 타임 아웃을 설정하여 SLEEP(5)와 같은 동작을 통해 참/거짓을 추측하는 것을 어렵게 할 수 있습니다.
- 쿼리의 결과를 얻을 수 없어 많은 횟수를 시도해야 하기에 지속적인 시도가 감지되면 차단하는 등의 방법도 있습니다.
