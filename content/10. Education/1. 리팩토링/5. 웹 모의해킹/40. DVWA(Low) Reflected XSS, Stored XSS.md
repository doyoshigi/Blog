칼리 리눅스에 DVWA를 설치하여 Security Level을 Low로 설정했습니다.

## Reflected XSS
### Reflected XSS 취약점이란?
**XSS 취약점이란?**
XSS(Cross Site Scripting) 취약점이란 공격자가 웹사이트의 취약점을 이용해 악성 스크립트를 삽입하고 이를 웹사이트 방문자의 브라우저에서 실행시킬 수 있는 취약점입니다.

![[Pasted image 20251212221049.png]]

Reflected XSS 공격이란 공격자가 악성 스크립트를 포함한 URL을 생성하여 피해자에게 전달하고 피해자가 URL을 클릭하면 서버에 악성 스크립트가 요청과 함께 전달됩니다.

서버는 전달받은 악성 스크립트를 포함한 응답을 전송하고 클라이언트에서 실행됩니다.

서버의 입장에서는 피해자가 스크립트를 삽입한 주체로 보이기 때문에 실제 공격자가 누군지 특정할 수 없게 됩니다.

DVWA 페이지에서 'XSS (Reflected)' 탭으로 이동하면 이름 입력창과 제출 버튼을 확인할 수 있습니다.

![[Pasted image 20251212221113.png]]

`MyName`을 입력창에 입력하고 제출해본 결과 쿼리 파라미터와 입력창 하단에 입력한 값이 나타나는 것을 확인했습니다.

![[Pasted image 20251212221120.png]]

입력창이 아닌 쿼리 파라미터에 `TEST`를 입력한 결과 입력창 하단에 TEST가 나타나는 것을 볼 수 있습니다.

![[Pasted image 20251212221125.png]]

TEST뒤에 `<script>alert(1)</script>`를 입력한 결과 아래와 같이 alert 팝업이 나타나는 것을 확인할 수 있습니다.

따라서 해당 페이지에 XSS 공격을 할 수 있다는 것을 확인했습니다.

![[Pasted image 20251212221133.png]]

`view-source:`를 통해 서버로부터 받은 HTML 응답을 확인해보면 빨간색 박스로 표시한 부분에 쿼리 파라미터에 입력한 값이 그대로 들어있는 것을 확인할 수 있습니다.

따라서 쿼리 파라미터에 입력한 값이 서버에 전달되고 다시 클라이언트로 반사(Reflect)되었다는 것을 알 수 있습니다.

![[Pasted image 20251212221139.png]]

`<script>alert(document.cookie)</script>`를 입력하여 쿠키값을 출력시켰습니다.

공격자는 악성 스크립트를 입력하고 피해자에게 링크를 클릭하도록 유도하여 XSS 공격을 할 수 있습니다.

#### Reflected XSS 소스코드
![[Pasted image 20251212221156.png]]
![[Pasted image 20251212221159.png]]

소스코드를 확인해보면 쿼리 파라미터의 값을 받아서 $html에 할당하고 그것을 response body에 출력하는 것을 볼 수 있습니다.

이 과정에서 아무런 필터링 등의 동작도 하지 않기 때문에 XSS 공격에 악용될 수 있습니다.

### 대응방안
- 초기 HTML 응답에는 사용자의 입력을 반사하지 않도록 합니다.
- 에러/검색/리다이렉트 메시지 등 반사가 일어날 수 있을만한 지점을 점검하여 반사 지점을 최소화합니다.
- document.write, innerHTML, outerHTML 등 HTML 구조를 직접 삽입하는 API 대신 innerText, textContent와 같은 안전한 속성을 사용합니다.
    - 불가피하게 사용해야 할 경우 입력값을 필터링하고 스크립트 동작이 불가능하게 처리합니다.
- 사용자 입력, 쿼리 파라미터 등 외부 값은 반드시 필터링하며 HTML 엔티티 치환을 통해 HTML, JS 코드로 해석되지 않게 처리합니다.
- DOMPurify 등의 검증된 라이브러리를 통해 HTML Sanitization을 실행하여 코드 내 위험 요소를 필터링합니다.
- CSP(Content Security Policy)를 적용하여 신뢰받는 스크립트 소스만 실행 가능하도록 하여 악성 스크립트의 실행을 제한합니다.
- React, Angular 등 최신 프레임워크의 내장 XSS 방지 기능을 활성화합니다.

## Stored XSS
### Stored XSS 취약점이란?
**XSS 취약점이란?**
XSS(Cross Site Scripting) 취약점이란 공격자가 웹사이트의 취약점을 이용해 악성 스크립트를 삽입하고 이를 웹사이트 방문자의 브라우저에서 실행시킬 수 있는 취약점입니다.

![[Pasted image 20251212221317.png]]

Stored XSS 공격이란 공격자에 의해 악성 스크립트가 서버에 저장되어 사용자가 해당 데이터를 요청할 때 해당 악성 스크립트가 클라이언트에 전달되어 실행되게 되는 공격입니다.

Stored XSS는 XSS의 대표적인 유형입니다.

#### Stored XSS 소스코드
![[Pasted image 20251212221432.png]]

소스코드를 확인해보면 사용자로부터 메시지와 이름을 받아서 DB에 안전하게 SQL 이스케이프만 진행하고 그대로 DB에 저장하는 것을 볼 수 있습니다.
