![[Pasted image 20251212205942.png]]

칼리 리눅스에 DVWA를 설치하여 Security Level을 Low로 설정했습니다.

## Weak Session IDs
### Weak Session IDs 취약점이란?
**세션 ID란?**
세션 ID는 웹 서버가 사용자를 식별하는 고유 값입니다. 서버는 세션 ID를 쿠키를 통해서 전달받고 사용자를 식별하게 됩니다.

Weak Session IDs 취약점이란 세션 ID가 추측 가능하거나 쉽게 예측되는 경우나, 공격자가 세션 ID를 탈취하여 사용자의 권한을 도용하기에 충분한 Session Timeout(세션 만료시간)이 설정되어 있을 경우 공격자가 획득한 세션 ID를 악용하여 다른 사용자의 권한으로 시스템에 접근할 수 있는 취약점을 말합니다.

### Weak Session IDs 실습
![[Pasted image 20251212215919.png]]

DVWA 페이지에서 'Weak Session IDs' 탭으로 이동하면 Generate 버튼을 확인할 수 있습니다.

버튼 위의 텍스트를 읽어보면 해당 버튼을 누르면 dvwaSession이라는 세션 ID가 쿠키에 저장된다고 쓰여있습니다.

![[Pasted image 20251212215930.png]]

BurpSuite를 켜고 Generate 버튼을 누른 후 BurpSuite의 Proxy>HTTP history 탭을 들어가서 해당 요청의 Response를 확인해보면 dvwaSession이란 값이 쿠키에 추가되는 것을 볼 수 있습니다.

![[Pasted image 20251212220027.png]]

계속해서 시도한 결과 세션 ID가 1씩 일정하게 증가하는 것을 확인할 수 있습니다.

이를 통해서 공격자는 쿠키를 조작하여 다른 사용자의 세션 ID를 사용하여 타 계정을 도용하거나 권한을 탈취할 수 있습니다.

#### Weak Session IDs 소스코드
![[Pasted image 20251212220044.png]]

소스코드를 확인해보면 세션 ID가 0부터 시작하여 요청이 올 때마다 1씩 증가되는 것을 볼 수 있습니다.

이러한 세션 ID 설정은 세션 ID를 쉽게 예측할 수 있게 하며 Weak Session IDs 취약점을 야기합니다.

### 대응방안
- 순차증가나 시간기반 등 예측 가능한 패턴이나 취약한 해시, 암호 알고리즘은 피하고 암호학적으로 안전한 난수 생성기( CSPRNG, Cryptographically Secure Pseudo-Random Number Generator)를 사용해야하며 SHA-256 등 강력한 해시, 난수 생성 알고리즘을 사용해야 합니다.
- 세션 ID를 전송할 때에는 HTTPS를 사용하여 전송하여 네트워크 상에서 탈취를 방지합니다.
- 쿠키에 Secure, HttpOnly, SameSite 옵션을 설정하여 외부 스크립트 접근을 차단하고 보호합니다.
- 세션 만료시간(Session Timeout)을 짧게 설정하여 유출 시 무한정 악용되는 것을 방지합니다.
- 로그인, 중요 권한 변화 등의 이벤트 발생 시 세션 ID를 재발급(Session Rotation)을 통해 세션 고정 공격(Session Fixation)을 차단하고 다시 유출되더라도 무한정 악용되는 것을 방지합니다.
- Django 등의 주요 웹 프레임워크에 내장 세션 관리 기능으로 쿠키 변조 방지 등을 통해 공격면을 줄일 수 있습니다.

## XSS(DOM)
### DOM-based XSS 취약점이란?
**XSS 취약점이란?**
XSS(Cross Site Scripting) 취약점이란 공격자가 웹사이트의 취약점을 이용해 악성 스크립트를 삽입하고 이를 웹사이트 방문자의 브라우저에서 실행시킬 수 있는 취약점입니다.

![[Pasted image 20251212220147.png]]

DOM-based XSS 취약점이란 URL 등과 같은 외부 값을 클라이언트 측 자바스크립트에서 DOM(Document Object Model)을 변경할 때 적절한 검증없이 동적으로 반영되어, 악성 스크립트가 브라우저에서 직접 실행되는 취약점을 말합니다.

### DOM-based XSS 실습
![[Pasted image 20251212220322.png]]

DVWA 페이지에서 'XSS (DOM)' 탭으로 이동하면 언어를 선택하는 메뉴를 확인할 수 있습니다.

![[Pasted image 20251212220337.png]]

영어로 언어를 선택하고 Select 버튼을 누르면 URL에 `default=English`라는 쿼리 파라미터가 생긴 것을 확인할 수 있습니다.

![[Pasted image 20251212220345.png]]

default 쿼리 파라미터에 임의의 값으로 `TEST`를 입력한 결과 페이지의 언어 목록에 입력한 TEST가 생긴 것을 확인할 수 있었습니다.

![[Pasted image 20251212220357.png]]

`view-source:`를 통해 서버로부터 받은 HTML 응답을 확인해보면 빨간색 박스로 표시한 부분에 `TEST`가 없는 것을 확인할 수 있었습니다.

이는 아까 봤던 TEST가 서버에서 랜더링되는 것이 아닌 클라이언트에서 DOM 구성 시 쿼리 파라미터에서 값을 가져와 리스트에 추가한다는 것을 의미합니다.

초록색으로 표시한 부분을 확인해보면 위의 동작이 나타나 있습니다.

쿼리 파라미터 default의 값이 직접적으로 DOM에 추가되기 때문에 이를 이용하여 XSS 공격을 할 수 있음을 확인했습니다.

방금 확인했던 HTML 문서를 바탕으로 클라이언트가 JavaScript를 사용한다는 것을 알았습니다.

따라서 쿼리 파라미터에 JavaScript 스크립트를 입력하면 클라이언트가 이를 실행할 것입니다.

![[Pasted image 20251212220414.png]]

`default=TEST<script>alert(document.cookie)</script>`를 입력하여 쿠키값을 출력시켰습니다.

공격자가 이를 악용하여 URL에 악의적인 스크립트를 입력하고 유저가 이를 클릭하면 XSS 공격이 이루어질 수 있습니다.

### 대응방안
- document.write, innerHTML, outerHTML 등 HTML 구조를 직접 삽입하는 API 대신 innerText, textContent와 같은 안전한 속성을 사용합니다.
    - 불가피하게 사용해야 할 경우 입력값을 필터링하고 스크립트 동작이 불가능하게 처리합니다.
- 사용자 입력, 쿼리 파라미터 등 외부 값은 반드시 필터링하며 HTML 엔티티 치환을 통해 HTML, JS 코드로 해석되지 않게 처리합니다.
- DOMPurify 등의 검증된 라이브러리를 통해 HTML Sanitization을 실행하여 코드 내 위험 요소를 필터링합니다.
- CSP(Content Security Policy)를 적용하여 신뢰받는 스크립트 소스만 실행 가능하도록 하여 악성 스크립트의 실행을 제한합니다.
- React, Angular 등 최신 프레임워크의 내장 XSS 방지 기능을 활성화합니다.
