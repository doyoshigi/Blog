# DVWA(Low) Command Injection, Brute Force
## 실습 환경
![[Pasted image 20251212205942.png]]

칼리 리눅스에 DVWA를 설치하여 Security Level을 Low로 설정했습니다.

## Command Injection
### Command Injection이란?
Command Injection이란 웹 애플리케이션 등에서 사용자의 입력값이 OS 명령어를 실행하는 함수에 직접적으로 전달되어 공격자가 임의의 시스템 명령어를 실행할 수 있는 공격방법입니다.

사용자가 입력한 값이 검증 없이 시스템 명령어 실행 구문(system(), exec()) 등에 포함될 때 발생합니다.

해당 애플리케이션을 실행하고 있는 운영체제 계정의 권한을 공격자가 그대로 사용 가능하므로 파일 삭제, 정보 누출, 루트 권한 탈취 등의 피해가 발생할 수 있습니다.

### Command Injection 실습
![[Pasted image 20251212205218.png]]

DVWA 실습 페이지의 왼쪽 탭에서 'Command Injection' 탭을 눌러보면 IP주소를 입력하여 Ping 명령어를 실행하고 그 결과를 출력하는 페이지가 나옵니다.

![[Pasted image 20251212205226.png]]

시험삼아 '127.0.0.1'을 입력해보면 입력한 IP주소에 PING을 보내고 그 결과를 출력해주는 것을 확인할 수 있습니다.

![[Pasted image 20251212205232.png]]

이 페이지의 소스코드를 확인해보면 사용자의 입력값이 저장되는 `target`이 필터링 없이 `shell_exec`함수를 통해 실행되는 것을 볼 수 있습니다.

사용자가 입력한 값이 `ping [사용자 입력값]` 구조로 명령어가 실행됩니다.

따라서 세미콜론(;) 등의 다중 명령어를 입력할 수 있는 특수문자를 입력 후 뒤에 실행하고 싶은 명령어를 입력하면 Command Injection을 할 수 있습니다.

![[Pasted image 20251212205241.png]]

`127.0.0.1; cat /etc/passwd`명령어를 입력하여 서버의 `/etc/passwd` 파일을 출력하도록 했습니다. `/etc/passwd` 파일은 리눅스 시스템의 사용자 계정 정보가 저장된 파일입니다.

PING 명령어가 실행된 후 `cat /etc/passwd`의 결과가 출력되는 것을 확인할 수 있습니다.

cat 이외에도 DVWA 앱을 실행중인 운영체제 계정의 권한에 따라서 다양한 명령어를 직접 실행할 수 있습니다.

### 대응방안
- 코딩 시 shell_exec, system, exec 등과 같이 입력받은 명령어를 shell에 직접 실행하는 함수를 사용하지 않고 언어에서 제공하는 안전한 함수를 사용합니다.
- 사용자의 입력값을 신뢰하지 않고, 입력이 허용된 값만 통과시키는 화이트리스트 정책을 사용합니다.
- 다중 명령어를 입력할 수 있는 특수문자의 입력을 제안해야 합니다.
- 해당 서버나 계정에 시스템 접근 권한을 최소로 부여해야 합니다.

## Brute Force
### Brute Force란?
Brute Force란 비밀번호나 암호화 키, 로그인 정보 등 보호된 데이터를 알아내기 위해 가능한 모든 조합을 체계적으로 반복해서 시도하는 공격을 의미합니다.

무차별 대입 공격이라고 불립니다.

### Brute Force 실습
![[Pasted image 20251212205522.png]]

DVWA 실습 페이지의 왼쪽 탭에서 'Brute Force' 탭을 눌러보면 로그인 창이 나옵니다.

![[Pasted image 20251212205603.png]]

Burp Suite를 실행하고 아무 값이나 입력하여 로그인 버튼을 누릅니다.

![[Pasted image 20251212205617.png]]

Burp Suite를 통해 가로챈 패킷을 확인해보면 입력한 username과 password를 확인할 수 있습니다.

![[Pasted image 20251212205625.png]]

이제 Brute Force 공격을 하기 위해 BurpSuite의 Intruder 탭으로 이동하여 방금 가로챈 패킷을 복사하여 붙여넣습니다.

그리고 Cluster bomb attack을 선택합니다. 이 공격 타입은 지정한 payload에 가능한 모든 조합을 테스트할 수 있습니다.

`username`과 `password` 파라미터 을 `Add §` 버튼을 눌러 페이로드 리스트에 추가합니다.

![[Pasted image 20251212205639.png]]
![[Pasted image 20251212205646.png]]

그 후 Payload configuration에서 대입에 사용할 아이템들을 각각 설정한 후 `Start attack` 버튼을 눌러 공격을 시작합니다.

![[Pasted image 20251212205658.png]]

각 조합을 실행한 결과가 리스트업 된 것을 확인할 수 있습니다. 이 중에서 하나의 응답의 길이가 다른 응답들과 달리 긴 것을 확인할 수 있습니다.

![[Pasted image 20251212205705.png]]

위에서 확인한 값을 로그인 창에 입력하면 로그인에 성공한 것을 확인할 수 있습니다.

### 대응방안
- 대소문자, 숫자, 특수문자를 조합한 긴 비밀번호(10자리 이상 등)를 사용하도록 정책을 강화합니다.
- 일정 횟수 이상 로그인 실패 시 계정을 일시 잠금하거나, 추가 인증이 필요하도록 설정합니다.
- CAPTCHA를 적용하여 사람이 아닌 자동화 도구의 접근을 차단합니다.
- 비밀번호 외에 OTP, SMS 코드 등의 추가 인증 절차를 설정합니다.
- WAF(Web Application Firewall, 웹 방화벽)에 자동화 공격을 탐지하고 차단하는 시스템을 구축합니다.
