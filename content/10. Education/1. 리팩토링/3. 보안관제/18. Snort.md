# Snort
## Snort란?
- Snort란 1998년에 오픈소스 기반의 네트워크 침입 차단 시스템(NIPS, Network Instrusion Prevention System)이자 네트워크 침입 탐지 시스템(NIDS, Network Instrusion Detection System)으로 개발되었습니다.
- 실시간 트래픽 분석 및 패킷 로깅이 가능한 IPS입니다.

## Snort의 3가지 기능
- Packet Sniffer: 네트워크 패킷을 읽고 콘솔에 보여주는 기능을 합니다.
- Packet Logger: 네트워크 패킷을 읽고 디스크에 기록하여 디버깅에 활용할 수 있도록 합니다.
- IDS/IPS: 네트워크 트래픽 분석, 침입 탐지 및 차단 기능을 합니다.

## Snort 작동 방식
![[Pasted image 20251210155100.png]]

1. 패킷 스니퍼
    - OS의 패킷 캡처 라이브러리를 이용하여 실시간으로 네트워크 인터페이스의 모든 트래픽을 캡처합니다.
2. 프리 프로세서
    - 전처리기를 통해 패킷을 디코딩하거나 TCP 스트림을 조립하는 등의 전처리를 합니다. 이를 통해 탐지 효율성을 높일 수 있습니다.
3. 탐지 엔진
    - 사전에 정의된 Snort 규칙과 비교하여 일치 여부를 판단합니다.
4. 출력
    - 탐지 결과를 콘솔, 파일, DB 등으로 출력합니다.

## Snort Rule Signatrue
![[Pasted image 20251210155203.png]]

- Snort Rule은 Rule Header와 Rule Option 섹션으로 구분됩니다.
- Rule Header는 규칙의 액션, 프로토콜, source destination의 IP와 Port, 넷마스크를 포함하고 있습니다.
- Rule Option은 alert 메시지와 규칙이 적용될 패킷의 부분에 대한 정보를 포함하고 있습니다.

### Rule Header
- Rule Header에는 패킷을 특정할 수 있는 정보와 해당 패킷이 나타났을 때 수행할 작업에 대한 정보들을 가지고 있습니다.
- 헤더가 포함하는 항목은 Rule Action, protocol, IP address, Port Numer가 있습니다.

### Action
- Action은 Snort가 규칙에 매칭되는 패킷을 찾았을 때 무엇을 할지 정해줍니다.
- 기본적으로 alert, log, pass 액션이 있으며 inline 모드로 사용할 경우 drop, reject, sdrop 액션을 추가적으로 사용할 수 있습니다.
    - alert: 선택된 alert 방식을 통해 alert를 생성하고 해당 패킷을 기록합니다.
    - log: 해당 패킷을 기록합니다.
    - pass: 해당 패킷을 무시합니다.
    - drop: 패킷을 차단하고 로그를 기록합니다.
    - reject: 패킷을 차단하고, 기록하며 프로토콜이 TCP라면 TCP reset 메시지를, UDP라면 ICMP port unreachable 메시지를 발신합니다.
    - sdrop: 패킷을 차단하지만 기록은 하지않습니다.
- 실무에서는 alert를 많이 사용합니다.

### Procotol
- Protocol 항목은 Snort가 분석할 프로토콜을 정의합니다.
- 분석할 수 있는 프로토콜은 TCP, UDP, ICMP, IP가 있습니다.
- 대부분 악성 행위는 TCP로 많이 일어나기 때문에 TCP를 많이 사용합니다.

### IP Adrdress
![[Pasted image 20251210155359.png]]

- IP주소를 정의하는 항목입니다.
- CIDR 표기법으로 표시하며 any 키워드를 사용하면 모든 IP 주소를 매칭시킬 수 있습니다.
- !(negation operator)는 뒤에 따라오는 IP주소만을 제외하고 모든 주소를 매칭한다는 의미힙니다.
- 또한 대괄호로 묶고 ,로 구분하여 IP주소 리스트도 사용할 수 있습니다.

### Port Number
![[Pasted image 20251210155442.png]]

- any는 어떤 포트 번호라도 매칭시킵니다.
- 단일 숫자일 경우 해당 포트만 매칭시킵니다.
- :(range operator)를 사용하여 매칭되는 포트 범위를 설정할 수 있습니다.
- 예시
    - 1:100
        - 1~100까지의 포트 번호를 매칭시킵니다.
    - :100
        - 100이하의 포트 번호를 매칭시킵니다.
    - 1:
        - 1이상의 포트 번호를 매칭시킵니다.
- IP와 마찬가지로 !를 통해 해당 포트 번호만 제외하고 매칭되게 할 수 있습니다.

### Direction Operator
![[Pasted image 20251210155513.png]]

- -> : 왼쪽(Source)에서 오른쪽(Destination)으로 가는 패킷을 탐지합니다.
- <> : 양쪽의 Host에서 주고받는 모든 패킷을 탐지합니다.
- <-는 없으니 주의하셔야 합니다.

- 일반적으로 IP와 port번호는 우회가 쉬우므로 any any를 사용하여 매칭시킵니다.

## Rule Option
- Option은 실제로 공격 감지 엔진의 로직을 구성합니다.
- 모든 Option은 ;로 구분되며 키워드 옆에 :을 쓰고 argument를 입력할 수 있습니다.
- 일반적으로 general, payload, non-payload, post-detection에 대한 옵션이 있습니다.

- general : 룰에 대한 정보를 제공하지만 매칭동안 아무런 역할을 하지 않습니다.
- payload: 패킷 페이로드 내부의 데이터를 검사하는 옵션입니다.
- non-payload: 페이로드 데이터가 아닌 것들을 검사하는 옵션입니다.
- post-detection: 룰이 발동된 후에 발생하는 규칙에 특화된 옵션입니다.

## 예시
alert tcp any any -> 192.168.1.10 80 (msg:"Possible XSS attempt"; content:"\<script\>"; nocase; sid:1000001; rev:1;)

- 본문의 내용을 토대로 해당 예시를 분석해보면 destination이 192.168.1.10 80인 TCP 패킷 중에 content에 "\<script\>"라는 내용이 들어있으면 "Possible XSS attempt"라는 메시지로 alert를 한다는 것을 알 수 있습니다.
