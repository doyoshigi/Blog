# 동적, 정적분석 툴 사용법 정리
## 1. 정적분석 툴
### 1.1 파일에 포함된 문자열 확인 툴
#### 1.1.1 BinText
- BinText는 파일의 binary에 포함된 문자열을 보여주는 툴입니다.
- 파일 내부에서 사용하는 메시지, URL, DLL, API 등의 정보를 유추할 수 있습니다.
- 패킹된 파일을 스캔할 경우 제대로된 정보가 나오지 않을 수 있어 언패킹을 진행한 후에 사용해야 합니다.

![[Pasted image 20251210114300.png]]

툴을 실행한 후 Browse로 스캔하고 싶은 파일을 선택하고 Go 버튼을 누르면 스캔이 시작됩니다.

![[Pasted image 20251210114315.png]]

스캔이 완료되면 해당 파일의 문자열들이 표시됩니다.

#### 1.1.2 Strings
- Strings는BinText처럼 바이너리 파일에서 문자열을 추출하기 위한 툴입니다.

![[Pasted image 20251210114347.png]]

Strings를 실행하기 위해서는 cmd에서 Strings가 있는 디렉토리로 이동해야 합니다. 그리고 Strings를 입력하게 되면 위의 사진처럼 정상적으로 실행되는 것을 볼 수 있습니다.

![[Pasted image 20251210114355.png]]

위처럼 "Strings [옵션] <파일이름>"을 입력하게 되면 해당 파일을 스캔할 수 있습니다.

![[Pasted image 20251210114404.png]]

실행 결과는 위와 같습니다.

### 1.2 패킹 관련 툴
#### 1.2.1 Exeinfo PE
- Exeinfo PE는 PE가 어떤 언어로 컴파일 되었는지와 패킹 여부를 확인할 수 있습니다.
- 만약 패킹이 되어있다면 어떤 툴을 사용하여 패킹을 했는지도 확인할 수 있습니다.

![[Pasted image 20251210114525.png]]

먼저 오른쪽 가장 상단에 있는 파란색 폴더 모양의 버튼을 눌러 exe 혹은 dll 파일을 불러옵니다.

![[Pasted image 20251210114534.png]]

파일을 불러오면 자동으로 스캔이 되며 예시 결과는 위와 같습니다.

해당 파일에 대한 정보중 하단에 있는 정보를 살펴보면
- Image is 64bit executable : 64bit로 구동된다는 것을 나타냅니다.
- 바로 하단의 창 : 어떤 언어로 컴파일되어 있는지를 나타냅니다.
- Lamer Info : 패킹의 여부와 패킹이 되어 있다면 언패킹할 수 있는 힌트를 제공합니다. 현재 예시 파일은 너무 크다고 경고 메시지가 나타나 있습니다. 뒤에는 패킹이 되어있지 않다는 내용이 나와있습니다.

#### 1.2.2 PEiD
- 위의 Exeinfo PE와 마찬가지로 패킹 여부와 만약 패킹되어 있다면 어떤 툴로 패킹했는지 표시하는 툴입니다.
- 64비트는 지원하지 않는다는 단점이 있습니다.

![[Pasted image 20251210114611.png]]

오른쪽 상단에 있는 ... 버튼으로 파일을 불러오면 자동으로 결과가 나타납니다.

![[Pasted image 20251210114618.png]]

결과를 살펴보면 Nullsoft PiMP Stub [Nullsoft PiMP SFX] *라는 패킹 툴로 패킹이 되어 있는 것을 확인할 수 있습니다. 만약 패킹이 되어있지 않다면 어떤 컴파일러로 컴파일되어 있는지를 확인할 수 있습니다.

#### 1.2.3 PEView
- PEView는 위의 2가지 툴과 마찬가지로 PE의 구조를 분석할 수 있는 툴입니다.
- 64비트 파일은 완전하게 지원하지 않는다는 단점이 있습니다.

![[Pasted image 20251210114715.png]]

프로그램을 실행하게 되면 즉시 PE파일을 브라우즈 하는 화면이 나타나고 파일을 선택하면 위와같은 화면이 나오게 됩니다.

![[Pasted image 20251210114723.png]]
![[Pasted image 20251210114732.png]]

PEView의 왼쪽 창을 보면 PE파일의 구조에 따라 데이터를 나눠서 해당 부분만 클릭하여 따로 볼 수 있습니다.

![[Pasted image 20251210114742.png]]

IMAGE_NT_HEADERS/IMAGE_FILE_HEADER 항목을 확인한다면 해당 파일의 동작환경, 섹션의 개수, 생성된 시기, 파일 형식 등의 메타데이터를 확인할 수 있습니다.

![[Pasted image 20251210114750.png]]

PEView로 해당 파일의 패킹 여부를 판단하는 방법은 PE파일의 세션을 확인할 때의 Virtual Size와 Size of Raw Data 값을 활용하는 것인데요.

위와 같이 두 값이 별 차이가 없고, Virtual Size값이 Size of Raw Data값과 거의 유사하거나 더 작다면 패킹이 되지 않았을 가능성이 더 큽니다.

또한 파일의 값이 .text, .data처럼 일반적이지 않다면 패킹의 의심이 가능합니다.

## 2. 동적분석 툴
###  2.1 CurrPort(cport) - 실시간 네트워크 연결 분석 툴
- CurrPort는 현재 열려있는 모든 TCP/IP, UDP 포트 목록을 볼 수 있는 툴입니다.
- 각 포트에 대해 해당 포트를 여는 프로세스의 이름, 버전, 전체 경로 등도 표시합니다.
- 작업관리자처럼 해당 포트를 여는 프로세스를 종료할 수 있으며 포트 정보를 저장할 수 있습니다.
- 식별되지 않은 프로그램(버전 정보, 아이콘이 없는)이 열고 있는 포트를 핑크색으로 표시합니다.

![[Pasted image 20251210114828.png]]

만약 과도한 트래픽이 발생하는 경우 어떤 프로세스에서 유발되는 지와 그 경로를 확인하는 것에 매우 유용합니다.

### 2.2 실시간 프로세스 모니터링, 작업관리 툴
#### 2.2.1 ProcessMonitor(ProcMon.exe)
- Process Monitor는 윈도우 운영체제에서 실행중인 프로세스들이 런타임에 호출하는 API를 실시간으로 모니터링 할 수 있는 툴입니다.

![[Pasted image 20251210114912.png]]

필터를 이용해서 특정 프로세스에서 발생하는 API 로그나 특정 종류의 API만을 필터링하여 볼 수 있습니다.

#### 2.2.2 ProcessExplorer(procexp.exe)
- ProcessExplorer는 마이크로소프트에서 제공하는 윈도우 시스템 모니터링 툴입니다. 현재 실행 중인 프로세스 목록 및 트리를 확인 가능합니다.

![[Pasted image 20251210114940.png]]

일단 실행하면 위처럼 각 프로세스의 CPU점유율, 메모리 할당량 등을 확인 가능합니다.

![[Pasted image 20251210114955.png]]

각 항목을 더블클릭 할 경우 프로그램의 경로, 실행 명령어, 환경변수를 확인할 수 있으며 만약 해당 프로세스가 비정상적이라고 판단된다면 바로 VirusTotal에 제출할 수도 있습니다.

![[Pasted image 20251210115013.png]]

또한 특정 프로세가 사용하는 DLL, 쓰레드, 파일 정보를 확인할 수 있습니다.

#### 2.2.3 SystemExplorer
- SystemExplorer는 위의 2가지 툴과 비슷하게 프로세스의 전반적인 정보를 표시하는 작업관리 툴입니다.
- 홈페이지의 DB나 Virustotal 사이트에서 의심스러운 프로세스를 바로 검색할 수 있어 편리합니다.
- 차이점은 Snapshot을 생성하여 파일, 레지스트리의 변화를 비교할 수 있다는 것입니다.

![[Pasted image 20251210115040.png]]

#### 2.2.4 Autoruns - 윈도우 시작프로그램 분석 툴
- Autoruns는 윈도우 부팅 후에 자동으로 시작되는 프로그램을 모니터링할 수 있는 툴입니다.
- 악성코드를 분석할 때 Snapshot을 만들어 의심되는 파일의 실행 전후 비교할 수 있습니다.

![[Pasted image 20251210115154.png]]

왼쪽 상단의 Save버튼을 통해 스냅샷을 저장하고 의심되는 프로세스를 실행한 후 한 번 더 스냅샷을 찍어 상단 메뉴의 File>Compare 버튼을 통해 비교해볼 수 있습니다.

### 2.3 실시간 네트워크 트래픽, 패킷 분석 툴
#### 2.3.1 Smart Sniffer(smsniff.exe)
![[Pasted image 20251210115223.png]]

실행했을 때의 모습입니다. 아직 캡처를 시작하지 않아 아무것도 보이지 않습니다.

왼쪽 상단의 캡처버튼을 눌러서 시작할 수 있습니다.

![[Pasted image 20251210115233.png]]
캡처를 시작하면 현재 해당 컴퓨터에서 주고받는 패킷이 기록되며 누르면 하단에 패킷의 데이터가 나오게 됩니다.

#### 2.3.2 Wireshark
- Wireshark도 스마트 스니퍼와 마찬가지로 컴퓨터에서 교환되고 있는 패킷을 캡쳐하고 분석할 수 있도록 도와주는 툴입니다.

![[Pasted image 20251210115259.png]]

위는 초기화면이고 아직 캡처를 시작하기 전 화면입니다. 캡처할 네트워크를 선택할 수 있으며 그래프로 네트워크 활동량이 표시되어 편리합니다.

![[Pasted image 20251210115306.png]]

캡처를 한 특정 패킷을 누르면 오른쪽 하단에는 그 패킷의 로우데이터가, 왼쪽에는 잘 정리된 데이터가 들어 있어 분석하기 편리합니다.
