# 웹 쉘(Web Shell)
## 1. 웹 쉘이란?
![[Pasted image 20251212194432.png]]

- 웹 쉘(Web Shell)은 웹 서버에 업로드되어 원격에서 시스템 명령을 실행할 수 있도록 하는 악성 스크립트 파일을 의미합니다.
- 웹 쉘은 웹(Web)과 쉘(Shell)의 합성어로 '웹'은 일반적인 웹 페이지(Web Page)를, '쉘'은 운영체제상에서 다양한 운영체제의 기능과 서비스를 구현하고 제공하는 프로그램을 의미합니다.
- 주로 php, jsp, asp 등 서버 사이드 스크립트 언어로 작성되며 공격자는 웹 서버의 취약점(특히 파일 업로드 취약점 등)을 이용하여 웹 쉘을 서버에 삽입합니다.

## 2. 웹 쉘의 특징
- 웹 서비스 포트는 항상 열려있어야 하며 공격자가 웹 쉘을 통해 서버에 명령을 보낼 때도 일반적인 웹 요청처럼 보여 정상적인 웹 트래픽으로 오인하기 쉽습니다.
    - 또한 HTTPS는 트래픽이 암호화되어 있기에 방화벽이나 IPS의 패킷 분석을 통해 웹 쉘 명령인지 정상 요청인지 구분할 수 없습니다.
    - 웹 쉘 자체가 서버 내부에 위치하기 때문에 패킷 내용을 확인하더라도 네트워크 장비 입장에서 특정 웹 리소스를 호출하는 요청일 뿐 내부에서 무슨 일이 벌어지는지 알 수 없습니다.
- 다양한 공격 수행이 가능합니다.
    - 웹 쉘을 통해서 공격자는 시스템 명령 실행, 파일 업로드/다운로드, 데이터베이스 조작, 계정 생성, 백도어 설치, 내부 정보 탈취 등 다양한 악성 행위를 할 수 있습니다.
- 탐지 회피를 합니다.
    - 웹 쉘은 난독화, 암호화될 수 있으며 일반적인 웹 애플리케이션 파일과 유사하게 작성되므로 백신 프로그램이 탐지하지 못하는 경우가 많으며, 시그니처 기반 탐지 우회도 가능합니다.
- 다양한 환경에서 실행 가능
    - 웹 서버의 언어만 맞으면 플렛폼에 상관없이 실행될 수 있으므로 다양한 운영체제에서 동작할 수 있습니다.
- 정상 파일로 위장할 수 있습니다.
    - 서버 사이드 스크립트 외에도 GIF, PNG, JPEG 등에 악성 스크립트를 삽입하여 위장이 가능합니다.
- 지속적인 시스템 장악 및 원격 제어가 가능합니다.
    - 단발성 공격이 아닌, 웹 쉘을 통해 서버에 지속적으로 접근하고 원격으로 제어할 수 있습니다.

## 3. 웹 쉘의 공격 방식
1. **취약점 탐식 및 이용**  
    공격자는 파일 업로드 취약점, 웹/WAS(Web Application Server)취약점, 설정 오류(Misconfiguration), SQL Injection 등 다양한 웹 애플리케이션의 취약점을 이용해 웹 쉘 파일을 서버에 업로드합니다.  
    파일 업로드 기능이 있는 웹 페이지, 확장자 우회, 인증 우회, 취약한 에디터 등을 통해 웹 쉘이 삽입될 수 있습니다.

2. **웹 쉘 파일 업로드**
    업로드된 웹 쉘은 서버 사이드 스크립(php, jsp, asp 등) 형태로 제작되어 웹 서버의 권한으로 실행됩니다.  
    업로드 과정에서는 확장자 우회, 인코딩, 난독화 등의 은폐 기법이 사용되어 탐지를 어렵게 합니다.  

3. **원격 명령 실행**  
    공격자는 웹 쉘을 통해 웹 서버에 접속, 명령어 실행, 파일 열람/수정/삭제/업로드, 백도어 설치, 데이터 탈취 등 다양한 악성 행위를 수행합니다.  
    서버 제어권 획득하면, 웹 페이지 소스코드 열람, 서버 내 자료 유출, 추가 악성코드 설치 등이 가능합니다.  

4. **추가 공격 및 피해 확산**  
    웹 쉘을 활용해 DDoS 공격, 악성코드 배포, 시스템 정보 탈취, 인접 시스템 공격 등 2차 피해로 이어질 수 있습니다.

### 3.1 웹 쉘의 주요 유형
- 바인드 쉘  
    공격 대상이 되는 호스트의 특정 포트에 바인딩되어 대기합니다. 공격자가 직접 해당 포트에 접속해 명령을 실행합니다.  

- 리버스 쉘  
    공격자가 포트를 열고 감염된 서버가 공격자에게 접속합니다. 그러면 감염된 서버는 공격자로부터 명령을 받을 수 있습니다.  

- 더블 리버스 쉘  
    공격 대상이 되는 호스트가 해커로부터 공격을 받는 포트가 아닌 별도의 포트로 해커의 장치에 연결되는 것입니다. 따라서 입력 트래픽 포트와 출력 트래픽 포트 등 서로 다른 두 개의 연결포트가 존재합니다.

## 4. 웹 쉘 관련 사건 사고
![[Pasted image 20251212194559.png]]

SKT는 2022년에 웹 쉘이 설치되었으며 2025년에 개인정보 유출 사고가 발생했습니다.  
2022년에 웹 쉘이 설치되어 조사하기 전까지 3년동안 서버의 웹 쉘을 탐지하지 못했습니다. 그리고 설치되어있던 악성코드는 32종이였습니다. 웹 쉘이 설치되고 웹 쉘을 통해 추가적으로 악성코드에 감염되었을 가능성이 있습니다.

![[Pasted image 20251212194609.png]]

2022년 8월 국내 반도체, 사출기, 리조트, 건설, 소프트웨어 업체 등 20여곳에서 웹 쉘에 의한 침해사고가 발생했습니다.
