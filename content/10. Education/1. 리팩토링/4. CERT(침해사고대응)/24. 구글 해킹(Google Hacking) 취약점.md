# 구글 해킹(Google Hacking) 취약점
## Google Hacking Database(GHDB)
이 글을 작성할 때 Exploit Database의 [GHDB](https://www.exploit-db.com/google-hacking-database)를 참고하여 작성했습니다. GHDB에는  취약점 정보, 로그인 페이지, 민감한 파일, 디렉토리 리스팅, 오류 메시지 및 설정 정보 등의 정보를 검색할 수 있는 Google Dork(검색 명령어)를 모아놓은 DB입니다.

구글링으로 찾을 수 있는 취약점을 알아보겠습니다.

## 1. 개인정보 노출
```
inurl:"wp-content/uploads" intitle:"Index of"
```
inurl:"wp-content/uploads"를 통해 워드프레스 웹사이트의 업로드 디렉토리 또는 그 하위 디렉토리를 찾을 수 있습니다.

또한 intitle:"Index of"를 통해 웹 서버가 생성한 디렉토리 목록 페이지를 찾아낼 수 있습니다.

따라서 inurl:"wp-content/uploads" intitle:"Index of"를 통해 워드프레스 사이트 중에서 사용자가 업로드한 파일이 저장되는 wp-content/uploads 디렉토리 파일 목록이 인터넷에 그래도 노출되어 있는 사이트를 찾아낼 수 있습니다.

![[Pasted image 20251211121725.png]]

검색어로 검색을 해보면 여러 사이트들이 나오는 것을 확인할 수 있습니다.

![[Pasted image 20251211121735.png]]

사이트로 들어가보면 여러 이미지 파일이 리스팅되어 있는 것을 볼 수 있습니다.

![[Pasted image 20251211121742.png]]

여기에는 미연방 경찰, 수사관의 신분증 이미지 사진이 그대로 노출되어 있었습니다.

![[Pasted image 20251211121749.png]]

심지어 Parent Directory로  이동하면 더 많은 정보들이 노출되어 있었습니다.

## 2. IoT/카메라 장비의 웹 인터페이스 노출
```
intitle:"Live View / - ASIX"
```

![[Pasted image 20251211121811.png]]
![[Pasted image 20251211121819.png]]

노출되어 있는 CCTV, 웹캠, IoT 장비 등에 접속할 수 있습니다.

만약 노출되어 있는 장비가 웹캠이나 인터폰의 카메라 등의 장비라면 사생활 침해가 발생할 수 있습니다.

IoT 장비 메뉴얼에는 초기 세팅 시 설정되어 있는 기본 아이디와 비밀번호가 있습니다. 사용자가 이를 따로 변경하지 않았다면 위협에 노출되게 됩니다.

## 3. 관리자 페이지 노출
```
intitle"admin login"
intitle:"admin"
```

![[Pasted image 20251211121835.png]]

관리자 로그인 페이지를 찾을 수 있습니다.

![[Pasted image 20251211121842.png]]

관리자에게만 노출되어야 할 관리자 페이지가 노출될 경우 무차별 대입 공격(Brute Force Attack)에 노출될 수 있습니다.
또한 아이디, 비밀 번호가 기본 설정이거나 학번 처럼 정해진 규격일 경우 예측이 더 쉬워질 수 있습니다.

## 4. 서버 디렉토리 페이지 노출
```
intitle:"Index of"
```

![[Pasted image 20251211121859.png]]

이 검색어를 통해서 웹 서버의 디렉토리 리스팅 페이지를 확인할 수 있습니다.

![[Pasted image 20251211121914.png]]

내부에는 사람의 얼굴 사진과 그 이름이 나와있는 사진 파일이 있었습니다.

![[Pasted image 20251211121920.png]]

또한 ParentDirectory로 가보면 더 많은 정보를 찾아볼 수 있었습니다.

![[Pasted image 20251211121928.png]]

거기에는 IP, 도메인 서버 설정, PHP 버전 등 매우 다양한 정보를 얻을 수 있었습니다.

서버의 디렉토리 페이지가 노출되면 어떤 정보가 노출될지 추적, 관리하기 어렵기 떄문에 애초부터 디렉토리 리스팅 기능을 사용하지 않거나 잘 막아놔야 한다고 생각합니다.

## 5. 데이터베이스 관리 페이지 노출
```
inurl:"/adminer.php"
```

![[Pasted image 20251211121940.png]]

PHP 데이터 베이스 관리도구인 Adminer의 로그인 페이지를 검색할 수 있습니다.

![[Pasted image 20251211121947.png]]

이는 관리자 페이지 노출 때와 마찬가지로 무차별 대입 공격(Brute Force Attack)에 노출될 수 있습니다.

## 6. 로그파일, 오류 메시지 노출
```
"PHP Fatal error:" ext:log OR ext:txt
```
인터넷에서 공개적으로 접근 가능하도록 잘못 설정된 로그 파일이나 텍스트 파일 중에서 "PHP Fatal error"가 기록된 파일을 찾아내는 검색어입니다.

![[Pasted image 20251211122016.png]]
![[Pasted image 20251211122019.png]]

"Fatal error"는 서버 내부 경로, 설정 정보, 소스 코드, 변수명, 서버 취약점 등의 매우 민감한 정보를 담고 있을 수 있습니다. 따라서 이런 로그가 담긴 파일이 노출될 경우 보안 위협을 초래할 수 있습니다.

## 7. 금융정보 노출
```
inurl:pastebin "VISA"
```
pastebin이라는 텍스트 공유 사이트내에서 "VISA"라는 단어가 포함된 게시물을 찾는 검색어입니다.
pastebin은 익명으로 글을 올리기 쉽기에 불법적인 정보가 유통되거나 공유되기도 합니다. 따라서 이 검색어는 이미 발생한 데이터 유출 사고의 결과물을 찾기에 유용합니다.

![[Pasted image 20251211122036.png]]
![[Pasted image 20251211122045.png]]

실제로 찾아보면 유출된 많은 카드 정보가 나옵니다.
