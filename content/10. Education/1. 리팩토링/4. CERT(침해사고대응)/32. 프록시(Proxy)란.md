# 프록시(Proxy)란
## Proxy란?
![[Pasted image 20251212202415.png]]

프록시(Proxy)란 네트워크 환경에서 서버와 클라이언트 사이에서 중계 또는 대리 통신을 수행하는 시스템을 의미합니다.

여기서 Proxy는 번역하면 대리, 중계로 번역할 수 있습니다.

위의 역할을 수행하는 장치, 프로그램을 프록시 서버(Proxy Server)라고 합니다.

클라이언트는 직접 Destination 서버에 연결하지 않고 중간에 위치한 프록시를 통해 통신함으로써 
여러가지 부가 기능과 이점을 제공할 수 있습니다.

## 프록시의 역할과 특징
- 클라이언트의 요청을 대신 받아 서버에 전달하고 서버의 응답을 대신 받아 클라이언트로 돌려주는 중계자 역할을 수행합니다.
- 클라이언트의 실제 IP정보는 서버에 직접 전달되지 않고, 프록시의 IP로 대체되어 노출됩니다.
- 자주 요청되는 데이터를 미리 저장하여 반복적인 요청에 대해 빠른 응답을 제공하여 네트워크 분하를 줄일 수 있습니다.
- 설정을 통해 특정 웹 사이트나 서비스에 대한 접속을 제어, 차단하는 보안관리 도구로 사용할 수 있습니다.
- 네트워크 사용 현황을 모니터링하고 로그를 기록하는 데에 사용할 수 있습니다. 

만약 프록시 없이 그냥 서버만 있을 경우 공격자가 서버에 바로 접근할 수 있지만 중간에 프록시가 있다면 공격자에게 노출되는 정보는 서버의 정보가 아니라 프록시 서버의 정보이므로 공격자가 접근할 수 있는 곳은 서버가 아니라 프록시이므로 서버를 보호할 수 있습니다.

## 프록시의 유형
프록시 서버가 사용되는 위치에 따라 Forward Proxy, Reverse Proxy 두 가지 유형으로 나눌 수 있습니다.

### Forward Proxy
![[Pasted image 20251212202440.png]]

Forward Proxy는 일반적인 프록시의 형태로, 프록시 서버가 클라이언트(사용자)와 인터넷 사이에 위치하여, 사용자의 요청을 외부에 전달하고 그 결과를 되돌려줍니다.

사용자가 외부 서버에 직접 접근하는 것이 아니라 포워드 프록시 서버에 먼저 요청을 보내면 프록시가 대신 외부 서버에 접근하여 정보를 받고 사용자에게 전달합니다.

**Forward Proxy의 장점**
- 회사망 등은 방화벽을 통해 인터넷 사용을 제한합니다. 여기서 방화벽 대신 Forward Proxy를 사용하여 정해진 웹 서버에만 접근할 수 있도록 제한할 수 있습니다.
- 사용자가 데이터를 요청하면 프록시는 해당 데이터를 요청하고 받아 사용자에게 전달하며 이를 캐싱하여 동일한 사용자 또는 다른 사용자가 해당 데이터를 다시 요청한다면 캐싱해 두었던 데이터를 보내 서버의 부하를 줄일 수 있습니다.
- 클라이언트를 대신하여 요청을 보낼 때 프록시 서버의 IP를 사용하기 때문에 요청을 받는 서버는 클라이언트의 IP를 알 수 없어 보안이 강화됩니다.

### Reverse Proxy
![[Pasted image 20251212202506.png]]

Reverse Proxy는 프록시 서버가 클라이언트와 웹 서버 사이에 위치하여 클라이언트의 요청을 서버가 직접 받는 것이 아닌 프록시 서버가 대신 받아 웹 서버에 전달하고 서버가 보낸 응답을 다시 클라이언트에게 전달합니다.

클라이언트가 실제 서버와 직접 통신하지 않고 리버스 프록시를 통해서 중계받게 됩니다.

**Reverse Proxy의 장점**
- 프록시가 트래픽을 로드 밸런싱(Load Balancing)하여 서버의 자원이 효율적으로 사용될 수 있도록 합니다.
- Forward Proxy와는 반대로 서버의 IP주소를 노출시키지 않을 수 있기 때문에 이로 인해 발생할 수 있는 DDoS 공격 등의 공격을 방지할 수 있습니다.
- 캐싱을 통해서 서버에 요청하지 않고 프록시가 캐싱된 데이터를 답변할 수 있어 서버에 부하를 줄일 수 있습니다.
- SLL 암호화, 복호화 작업을 프록시가 대신 처리하여 서버의 부담을 줄이고 보안 통신을 쉽게 구현할 수 있습니다.
