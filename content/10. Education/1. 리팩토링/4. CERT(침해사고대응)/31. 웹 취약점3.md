# 웹 취약점3
## 1. 크로스사이트스크립트(XSS) 취약점
![[Pasted image 20251212201414.png]]

크로스사이트스크립트(XSS, Cross Site Scripting) 취약점은 공격자가 악의적인 목적을 가지고 글쓰기가 가능한 게시판에 일반적인 텍스트가 아닌 스크립트 구문을 작성했을 때 스크립트가 검증 또는 필터링되지 않고 실행될 때 발생하는 취약점입니다.

피해자는 해당 글을 클릭했을 때 공격자가 입력한 스크립트가 실행되어 피해가 발생할 수 있습니다.

꼭 글쓰기가 가능한 게시판뿐만아니라 취약한 URL 매개변수, 홈페이지 내의 입력란에 사용자가 임이의 값을 입력할 때, 입력값에 대하여 검증되지 않은 상태로 저장이나 실행될 경우, 공격자가 웹 페이지에 악의적인 스크립트를 삽입시킬 수 있으며, 해당 페이지로 접근하는 사용자를 대상으로 악성 스크립트를 실행시킴으로써 개인정보 탈취, 홈페이지 위변조, 악성코드 감염 등의 다양한 공격을 유발할 수 있습니다.

### XSS의 유형
크로스사이트스크립트 취약점은 3가지의 유형이 있습니다.

#### Stored XSS(저장형 XSS)
![[Pasted image 20251212201439.png]]

- XSS의 대표적인 유형입니다.
- 악성 스크립트가 데이터베이스 등 서버에 저장되어 사용자가 해당 데이터를 요청할 때 스크립트가 실행됩니다.
- 공격자가 게시글을 작성하고 피해자가 해당 게시물에 접근하면 피해가 발생하는 구조입니다.
- 공격자가 게시글을 작성하기 때문에 서버의 입장에서 공격자가 누군지 정확하게 파악이 가능합니다.

### Reflected XSS(반사형 XSS)
![[Pasted image 20251212201450.png]]

- 공격자가 악성 URL을 생성하여 피해자에게 전달하고, 피해자가 해당 URL을 클릭하면 스크립트가 실행됩니다. 이때 스크립트는 서버로 요청과 함께 전성되고 피해자의 클라이언트가 서버로부터 받은 응답을 실행하면 악성 스크립트가 실행됩니다.
- 서버의 입장에서는 피해자가 스크립트를 삽입한 주체로 보이기 때문에 실제 공격자가 누구인지 알 수 없습니다.

#### DOM-based XSS(DOM 기반 XSS)
![[Pasted image 20251212201502.png]]

- 보안에 취약한 JavaScript코드로 DOM객체를 제어하는 과정에서 발생합니다.
- 브라우저가 서버로부터 받은 스크립트를 읽을 때 악성코드가 동작하여 DOM을 조작합니다.
- 서버는 공격 페이로드를 그대로 반환하거나 가공없이 전달할 뿐, 실제로 스크립트를 삽입하지는 않습니다.

### 대응방안
- 웹 서버에서 입력 값에 정의된 문자 길이를 검증하여 악성 스크립트 명령이 삽입되지 않도록 수정합니다.
- 사용자 입력 폼(로그인, 검색 폼, URL 등)을 대상으로 특수문자, 특수구문 필터링 규칙을 적용합니다.
- 사용자 입력값을 웹 페이지에 출력할 때 HTML로 해석되지 않도록 인코딩합니다.
- 웹 방화벽(WAF, Web Application Firewall)을 사용하여 비정상적인 데이터가 서버로 전달되는 것을 차단합니다.

## 2. SQL Injection 취약점
![[Pasted image 20251212201548.png]]

SQL Injection 취약점이란 웹 애플리케이션이 사용자 입력값을 적절히 검증하지 않고 SQL 쿼리에 직접 삽입할 때 발생하는 보안취약점입니다.

공격자는 입력 폼, URL 등 다양한 경로를 통한 악의적인 SQL 구문을 삽입하여 데이터베이스를 조작하거나, 민감한 정보를 탈취할 수 있습니다.

공격 난이도는 낮으나 피해 규모는 큰 파급력이 큰 취약점입니다.

![[Pasted image 20251212201555.png]]

웹 페이지의 입력 폼에 SQL 문법적 의미를 갖는 (')를 입력 시 SQL 에러 메시지가 반환된다면 SQL Injection 취약점이 존재한다고 볼 수 있습니다.

### SQL Injection의 공격 유형
#### Union SQL Injection
- Union Select문을 Injection하여 원하는 데이터를 조회합니다.

#### Error Based SQL Injection
- 데이터베이스의 문법에 맞지 않는 쿼리문 입력 시 반환되는 에러 정보를 기반으로 공격하는 방법입니다.
- 정보 획득이 가능한 에러 유발 함수를 이용하여 공격합니다.

####  Blind SQL Injection
- 애플리케이션이 SQL 쿼리의 결과를 직접적으로 응답하지 않아도 응답의 차이만으로 데이터베이스의 상태를 추측하는 방법입니다.
- 예를 들어 페이지의 정상 출력 유무를 통해 해당 데이터의 True/False를 추론할 수 있습니다.

### 대응방안
- Prepared Statement를 사용합니다.
    - SQL구문이 미리 컴파일되어 있고 입력값을 변수로 선언해두고 필요에따라 값을 대입하여 처리하는 방식입니다.
    - SQL 쿼리와 입력값을 분리하여 쿼리의 구조를 변조하는 것을 방지할 수 있습니다.
- 정규식(Regex)를 이용하여 화이트리스트 기반으로 한 입력값 필터링을 합니다.
- 중요한 정보가 노출될 수 있는 에러 메시지의 출력을 제한합니다.

## 3. 권한인증 취약점
![[Pasted image 20251212201716.png]]

웹 애플리케이션에서 사용자의 인증 또는 권한 검증이 미흡하게 구현되어, 권한이 없는 사용자가 중요 정보에 접근하거나 기능을 수행할 수 있는 보안 취약점입니다.

일반 사용자가 URL 매개변수 조작을 통해 권한이 없는 영역의 페이지에 접근할 수 있습니다.

관리자 권한으로 접근이 가능한 공지사항 글쓰기 메뉴에 허가되지 않은 사용자가 접근하여 임의의 글쓰기가 가능할 경우 홈페이지 관리자로 위장하여 악성코드 배포, 홈페이지 위변조가 가능합니다.

권한 인증 취약점에는 2가지 케이스가 있습니다.
1. 일반적인 사용자의 권한으로 허용되지 않은 곳에 접근할 경우
2. 중요한 정보나 설정 페이지에 접근 시 2차 인증을 요구하지 않을 경우

### 공격방식
- 공격자는 URL 파라미터를 조작하여 권한 설정이 미흡한 페이지에 무단 접근할 수 있습니다.
- 세션 ID가 예측 가능하거나 세션 관리가 미흡할 때, 공격자가 세션을 탈취해 권한을 도용할 수 있습니다.
- 쿠키에 저장된 사용자 정보를 조작하여 권한 상승을 시도할 수 있습니다.

### 대응방안
- 모든 요청에 대해 서버에서 권한 검증을 수행해야 합니다.
- 중요 페이지 및 기능에 2차 인증을 적용합니다.
- 예측 불가능한 세션 ID를 발급하고 세션 만료 시간을 설정합니다.
- 역할 기반 접근제어(ACL)을 적용하여 사용자마다 접근할 수 있는 권한을 최소한으로 설정합니다.

## 4. 에러처리 취약점
![[Pasted image 20251212201956.png]]

에러처리 취약점이란 웹 애플리에키션이나 서버에서 에러 발생 시 적절한 예외처리없이 상세한 에러 메시지나 시스템 정보를 사용자에게 노출하는 보안상의 문제를 의미합니다.

공격자는 에러메시지를 통해 서비스 내부 구조, 파일 경로, 데이터베이스 정보, 사용중인 소프트웨어 버전 등 공격에 유용한 정보를 획득할 수 있습니다.

### 대응방안
- 에러가 발생했을 때 사용자에게는 최소한의 안내 메시지만 제공합니다.
- 별도의 에러 페이지를 제작하여 에러 발생 시 해당 페이지로 리디렉션합니다.
- 로그 기록은 내부적으로만 관리되어야 합니다.
- 모든 예외 상황을 try-catch문으로 처리할 수 있도록 하며 예상치 못한 예외에도 안전하게 처리하도록 프로그래밍합니다.
