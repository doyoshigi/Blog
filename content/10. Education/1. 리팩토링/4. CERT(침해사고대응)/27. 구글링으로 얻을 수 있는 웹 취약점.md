# 구글링으로 얻을 수 있는 웹 취약점
## 1. 관리자 페이지 노출 취약점
![[Pasted image 20251212190753.png]]
![[Pasted image 20251212190756.png]]

관리자 페이지 노출 취약점이란 이름 그대로 관리자 페이지가 외부에 노출되어 있는 취약점을 말합니다.

여기에는 관리자 페이지가 /admin, /manage, /cms와 같이 예측하기 쉬운 URL 경우나 관리자 페이지의 공개된 링크가 노출되어 있는 경우도 있습니다. 그리고 구글링을 통해 해당 관리자 페이지가 검색되는 경우도 있습니다. 이 경우 권한이 없는 사용자가 페이지를 발견, 접근할 수 있습니다.

**보안 위협**
- 관리자 계정에 무차별 대입 공격(Brute Force Attack) 등으로 로그인하여 시스템 권한이 탈취될 수 있습니다.
- 페이지에 존재할 수 있는 취약점을 이용하여 SQL, 스크립트 인젝션 등의 공격에 노출될 수 있습니다.

**대응방안**
- robots.txt를 수정하여 관리자 페이지가 검색 엔진에 노출되지 않도록 설정해야 합니다.
- 관리자 페이지 URL을 /admin, /manage와 같은 일반적인 것이 아닌 예측하기 어려운 경로로 설정해야 합니다.
- 다중인증이나 로그인 시 CAPTCHA나 N회 실패 시 계정 잠금 기능 등을 통해 인증을 강화해야 합니다.
- 가장 좋은 방법은 사내 IP또는 VPN 전용 접속으로 설정하여 외부에서의 접속을 차단하는 것입니다.

## 2. 디렉토리 나열 취약점
![[Pasted image 20251212190918.png]]
![[Pasted image 20251212190922.png]]

디렉토리 나열 취약점은 디렉토리 리스팅(Directory Listing) 취약점 혹은 디렉토리 인덱싱(Directory Indexing) 취약점이라고도 하며  웹 서버의 미흡한 설정으로 인해 인덱싱(Indexing) 기능이 활성화 되어있을 경우 발생하는 취약점으로 디렉토리에 있는 파일 목록과 정보가 노출될 수 있습니다.

**보안 위협**
- 디렉토리 구조를 통해 내부 파일 구조가 노출될 수 있으며 이는 URL 경로를 유추하거나 숨겨진 관리자 페이지가 노출되는 등 2차적 피해를 야기할 수 있습니다.
- 또한 내부 파일의 내용을 확인할 수 있기 때문에 소스코드, 비밀번호, API키, 개인정보 등 중요 정보가 포함된 파일이 노출될 수 있습니다.

**대응방안**
- 웹 서버 설정에서 인덱싱 기능을 차단합니다.
- 디렉토리 내에 index.html 등의 인덱스 파일을 추가하여 해당 경로로 접근했을 때 인덱스 파일을 표시합니다.
- WAF(Web Application Firewall)을 사용하여 디렉토리 나열관련 요청, 응답을 차단합니다.

## 3. 시스템 관리 취약점
![[Pasted image 20251212191039.png]]

시스템 관리 취약점이란 서버 및 응용 프로그램 설치, 운영, 관리 과정에서 보안 설정 미흡, 불필요한 파일 방치, 인증 미적용 등의 관리 미흡으로 인해 발생하는 취약점을 말합니다.

위 사진에서는 SQL 로그 파일이 노출되어 있는 것을 볼 수 있습니다. 이 파일을 통해서 유저의 이름, 서버의 버전 등 노출되지 않아야 하는 정보들이 노출된 것을 볼 수 있습니다.

**보안 위협**
- 위의 사진처럼 불필요한 파일들로 인해 시스템 내부의 정보가 유출될 수 있습니다.
- 만약 원격 접속 창 등이 노출되면 공격자에게 내부 시스템의 접근을 허용할 수 있습니다.

**대응방안**
- 임시로 생성되는 파일은 필요하지 않다면 즉시 삭제합니다.
- 체크리스트를 만들어 정기적으로 불필요한 파일, 잘못된 설정 등을 점검하고 조치합니다.

## 4. 불필요한 Method 허용 취약점
![[Pasted image 20251212191124.png]]

불필요한 Method 허용 취약점이란 웹 서버에서 불필요한 HTTP Method들(PUT, DELETE, OPTIONS 등)을 불필요하게 허용할 때 발생하는 보안 취약점입니다.

일반적인 웹 서비스에서는 GET, POST 이외에 Method들을 허용할 필요는 없습니다. 하지만 위 사진의 웹 사이트는 OPTIONS, HEAD, TRACE를 추가적으로 허용하고 있습니다.

**보안 위협**
- PUT Method로 웹 서버에 파일 업로드나 서버 덮어쓰기가 가능합니다.
- DELETE Method로 웹 서버 파일 삭제가 가능합니다.
- OPTIONS Method로 지원 메서드 목록이 노출되며 공격자가 서비스 구조를 파악할 수 있습니다.
- TRACE Method로 XST(Cross Site Tracing) 공격이 일어날 수 있습니다.
- CONNECT Method로 프록시 터널링을 통해 악성 트래픽을 우회할 수 있습니다.

**대응방안**
- 웹 서버의 불필요한 HTTP Method를 비활성화합니다.
- WAF(Web Application Firewall)을 통해 불필요한 Method 요청이 수신될 경우 차단시킵니다.
