# 웹 취약점2
## 1. 파일 다운로드 취약점
![[Pasted image 20251212193127.png]]

파일 다운로드 취약점이란 외부에서 입력되는 값에 대해서 경로 조작에 사용될 수 있는 문자(../, %2e%2e%ef 등)을 검증하지 않고, 주요 시스템 파일이 저장된 경로에 접근 권한이 설정되어 있지 않을 경우, 공격자가 임의의 위치에 있는 파일의 다운로드를 할 수 있습니다.

![[Pasted image 20251212193135.png]]

PortSwigger Web Academy에서 제공하는 테스트 페이지를 사용했습니다.

![[Pasted image 20251212193143.png]]

해당 페이지를 살펴보면 이미지가 "/image?filename=66.jpg"로 가져오는 것을 확인할 수 있습니다.

![[Pasted image 20251212193149.png]]

이를 이용해 filename을 변형하여 리눅스 시스템의 주요 파일인 "/etc/passwd"를 다운로드해 보았습니다. 위 사진을 보면 정상적으로 다운로드가 되어 서버 정보가 출력되는 것을 확인할 수 있습니다.

**보안 위협**
- 공격자가 우회를 통해 다운로드한 파일 정보를 통해 2차 공격에 악용할 수 있습니다.

**대응방안**
- 시큐어 코딩을 통해 경로 조작 문자열을 필터링합니다.
- 다운로드 파일 이름을 DB에 저장하고 다운로드 요청 시 요청파일 이름과 비교하여 적정성 검증을 수행합니다.
- 시큐어 코딩을 통해 경로 조작 문자열을 필터링합니다.
    - 파일 경로 파라미터 변수에서 상위 경로를 의미하는 path traversal 문자열을 필터링합니다.
    - \[..\], \[../\], \[..\\]
- 다운로드가 가능한 위치는 고정적으로 설정하고 그 외 디렉터리에서는 다운로드가 불가능하도록 구현합니다.

## 2. 파일 업로드 취약점
![[Pasted image 20251212193259.png]]

파일 업로드 취약점이란 웹 어플리케이션에서 사용자가 파일을 서버에 업로드할 수 있을 때 업로드 된 파일에 대한 적절한 검증이나 필터링이 이루어지지 않아 공격자가 악성 스크립트 파일을 업로드하고 이를 실행시킬 수 있는 보안 취약점을 말합니다.

**보안 위협**
- 공격자는 웹 서버에 웹 쉘(Web Shell) 등 악성 파일을 설치하여 서버를 원격으로 제어하거나, 시스템 내부 정보를 탈취하고 추가적인 공격(권한 상승, 악성코드 배포 등)을 시도할 수 있습니다.
- 공격자가 사람들이 많이 사용하는 게시판 등에 악성 파일을 올리고 다른 사용자들이 그것을 다운받을 경우 피해가 더욱 커질 수 있습니다.

**대응방안**
- 화이트리스트 방식으로 허용할 파일 유형을 제한합니다.
- 업로드 파일에 대한 실행권한을 제거합니다.
- 업로드 파일을 위한 전용 디렉터리를 별도로 생성하여 해당 디렉터리에 대한 실행권한을 제거합니다.

## 3. 소스코드 내 중요정보 노출 취약점
![[Pasted image 20251212193348.png]]

소스코드 내 중요정보 노출 취약점이란 웹 페이지의 소스코드 또는 주석문에 민감한 정보(개인정보, 시스템 정보 등)가 배포 후에도 제거되지 않아 외부에 노출되는 보안 취약점을 말합니다.

![[Pasted image 20251212193356.png]]

위의 사진을 보면 어떤 DB를 사용하는지와 IP주소, port 번호, 유저명, 비밀번호, DB이름까지 하드코딩되어 있는 것을 확인할 수 있습니다.

**보안 위협**
- 소스코드 내 존재하는 정보를 통해 추가적인 공격이 가능해집니다.

**대응방안**
- 개발 완료 시 소스코드와 주석, 디버깅 코드 내 민감한 정보를 제거합니다. 그리고 정기적으로 이러한 정보가 있는지 점검해야 합니다.
- 비밀번호, 암호화 키, API 주소 등 중요 정보는 별도의 보안 저장소에 저장하고 권한 설정을 통해 관리합니다.
- 소스코드 노출이 발생할 수 있는 백업 파일, 로그 파일 등 불필요한 파일을 삭제합니다. 마찬가지로 정기적으로 점검해야 합니다.

## 4. 공개용 웹 게시판 취약점
![[Pasted image 20251212193432.png]]

공개용 웹 게시판 취약점이란 제로보드, 그누보드, 테크노트 등과 같은 오픈소스 기반으로 제작된 공개용 웹 게시판을 사용할 경우 각종 취약점에 대한 정보가 인터넷에 공개되어 있어 공격자가 이를 악용해 홈페이지 위변조, 해킹 경유지 활용, 파일 업로드 등 다양한 공격을 시도할 수 있는 취약점입니다.

![[Pasted image 20251212193441.png]]

위 사진을 보면 오픈소스 게시판인 제로보드를 사용한 게시판을 확인할 수 있습니다.

**보안 위협**
- 오픈소스의 취약점에 대한 정보가 인터넷에 그대로 노출되어 있기 때문에 공격자는 이를 악용하여 다양한 공격이 가능합니다.

**대응방안**
- 웹 서버에는 공개용 웹 게시판(제로보드, 테크노트, 세팔보드, 그누보드 등) 사용을 지양해야 합니다.
- 필요에 의해 사용해야 하는 경우, 보안 패치 또는 최신 버전의 제품으로 설치합니다.
- 정기적으로 게시판 배포 사이트에 방문하여 보안 취약점 정보를 확인합니다.
