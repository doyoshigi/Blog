## 1. AWS 보안 가이드 분석
1) **계정 및 접근 권한 관리 (Account and access management)**
	- **관리자 권한 노출 최소화:** 관리자 권한을 가진 계정을 다수 생성하는 것을 피하고, 최고 권한의 콘솔 관리자 계정을 일상적인 업무에 사용하는 것을 지양해야 합니다.
	- **자격 증명(Identity) 관리 원칙:** "1인 1 IAM 사용자" 원칙을 따르며, 한 사람이 여러 IAM 자격 증명을 보유하지 않도록 합니다.
	- **추적성 확보:** 감사 및 소유권 확인이 명확하도록 IAM 사용자에 식별 정보(예: 이름/이메일/부서)를 태그로 지정합니다.
	- **그룹 기반 접근 제어:** 권한은 IAM 그룹을 통해 관리하며, 불필요한 사용자가 특권 그룹에 포함되지 않도록 합니다.
	- **자격 증명 강화(Credential hardening):**
		- 인스턴스 접근 시 EC2 키 페어(2048-bit RSA PEM)를 사용하고, 프라이빗 키는 추측하기 어렵고 접근이 제한된 곳에 보관합니다.  
		- **관리 콘솔 액세스 키**는 사용/교체 정책을 통해 제어합니다(가이드의 "양호" 예시: 발급일 60일 이내, 최근 활동 30일 이내).
		- MFA(다중 요소 인증)를 강제합니다("양호" = MFA 활성화, "취약" = 비활성화).
		- 강력한 **비밀번호 정책**을 시행합니다(길이/복잡도 + 최대 사용 기간 등의 교체 주기).
	- **EKS 관련 접근 제어(명시적 언급):**
		- 클러스터 등록 사용자(aws-auth)를 제한하고, 클러스터 생성 시 **전용 IAM 역할**을 사용합니다(생성자는 제거 불가능한 `system:masters` 권한을 갖기 때문).
		- ServiceAccount 토큰의 자동 마운트를 비활성화합니다(`automountServiceAccountToken=false`가 "양호", `true`는 "취약").
		- `system:anonymous / system:unauthenticated`에 과도한 권한이 부여되지 않도록 RBAC 바인딩을 점검하여 불필요한 익명 접근을 방지합니다.
2) **권한 관리 (IAM 정책 모범 사례)**
	- 인스턴스 서비스, 네트워크 서비스 및 기타 서비스에 대한 IAM 권한이 해당 **역할/목적에 맞게 설정되었는지 확인**("양호")하고, 역할에 부적합한 경우("취약")를 식별합니다.
	- **FullAccess** 형태의 높은 권한 정책은 소수의 전담 인프라/관리자 자격 증명으로 제한합니다(가이드에서는 "Full Access 계정이 많은 경우"를 취약점으로 간주).
3) **가상 리소스 관리 (네트워크, 스토리지, 플랫폼 보안 태세)**
	- **보안 그룹(Security Groups):**
		- "양호" = `ANY`(0.0.0.0/0 등)로 설정된 인바운드/아웃바운드 규칙 없음, "취약" = `ANY` 존재.
		- 불필요한 인바운드/아웃바운드 규칙을 제거합니다.
	- **네트워크 ACL:** "모두 허용(allow all)" 형태의 정책을 지양하고, 인바운드/아웃바운드를 명시적으로 관리합니다.
	- **라우팅 테이블:** 꼭 필요한 경우를 제외하고 광범위한 `ANY` 경로 설정을 피합니다(가이드는 아웃바운드 게이트웨이가 필요한 경우 등 예외 사항 언급).
	- **NAT 게이트웨이:** 아웃바운드 연결이 필요한 곳에만 사용합니다(목적/필요성이 불분명할 경우 "취약").
	- **S3 접근 제어:** 의도치 않은 퍼블릭 액세스를 차단하고, 버킷/객체 정책을 적절히 구성하여 외부 노출을 방지합니다.
	- **RDS 서브넷/AZ 관리:** DB 서브넷 그룹에 불필요한 가용 영역(AZ)이 포함되지 않도록 합니다(진단 기준).
	- **EKS 파드(Pod) 보안:** Kubernetes Pod Security(PSS/PSA)를 사용하며, 가능한 경우 특권(privileged) 프로필보다 강력한 프로필(baseline/restricted)을 선호합니다.
	- **ELB 강화(Security Hub ELB 통제 참조):** 로깅 활성화, 삭제 방지 설정, TLS 리스너 구성, 다중 AZ(Multi-AZ) 적용, WAF 연동 등을 수행합니다.
4) **운영 관리 (암호화, 로깅, 보존, 백업)**
	- **저장 데이터 암호화(Data at rest):** EBS 볼륨 암호화(KMS 사용) 및 데이터베이스/스토리지 암호화를 활성화합니다(예: RDS는 암호화 활성화 시 AES-256 사용).
	- **전송 데이터 암호화(Data in transit):** "양호" = 통신 경로에 암호화 구성됨, "취약" = 구성되지 않음.
	- **사용자 활동 로깅:** AWS Console/IAM 활동이 로깅되는지 확인합니다(CloudTrail, 선택적으로 CloudWatch Logs 전송). "양호" 대 "취약" 기준이 명시되어 있습니다.
	- **서비스/인스턴스 로그 중앙화:** 로그를 CloudWatch 로그 스트림에 저장합니다(가이드에서 "양호"로 간주).
	- **네트워크 가시성:** VPC Flow Logs를 활성화합니다(활성화 시 "양호", 미활성화 시 "취약").
	- **보존 정책(Retention):** CloudWatch Logs의 기본 보존 기간은 "만료 없음(never expire)"이므로, 별도의 보존 기간을 설정합니다(가이드는 감사/접근 기록 1년 이상 보관 등의 컴플라이언스 기대치 참조).
	- **백업:** 문서화된 백업 정책(대상, 주기, 보존 기간, 소유권, 복원 절차)을 유지합니다. "양호" = 백업 정책 존재, "취약" = 없음.
	- **EKS 관측성 및 시크릿 보호:** EKS 컨트롤 플레인 로깅을 활성화하고 KMS 기반 시크릿 암호화를 활성화합니다("양호" 조건; 암호화 활성화 후에는 수정/제거가 불가능하다는 경고 포함).

### 디렉터리 구조
```
Project Root
├── main.tf # 로직 전체 (EC2, VPC, IAM 다 여기) 
├── variables.tf # 입력
├── outputs.tf # 출력
├── provider.tf # 설정
└── versions.tf # 버전
```
프로젝트의 디렉터리 구조는 위와 같다.

**versions.tf**
```hcl
terraform {  
  required_version = ">= 1.5.0"  
  required_providers {  
    aws = {  
      source  = "hashicorp/aws"  
      version = ">= 5.0"  
    }  
  }  
}
```
어떤 도구를 사용할지, 최소 버전은 무엇인지 정의한다. terraform 버전 1.5.0 이상, AWS를 다루는 플러그인인 “hashicorp/aws” 버전은 5.0 이상을 사용하도록 명시한다.

**provider.tf**
```hcl
provider "aws" {  
  region = var.aws_region  
}
```
“aws”라는 공급자를 사용하고, 리전을 정의한다. 리전은 “variables.tf”에서 정의한 곳으로 할당한다.

**variables.tf**
```hcl
variable "aws_region" {  
 type    = string  
 default = "ap-northeast-2"  
}  
variable "project_name" {  
 type    = string  
 default = "week4-secure-ec2"  
}  
variable "vpc_cidr" {  
 type    = string  
 default = "10.10.0.0/16"  
}  
variable "public_subnet_cidr" {  
 type    = string  
 default = "10.10.1.0/24"  
}
```
코드에서 자주 바뀌거나 중요한 값들을 따로 빼둔 파일이다. 위에서부터 aws 리전, 프로젝트 이름, VPC 네트워크 대역, 서브넷 네트워크 대역을 정의한다.

**main.tf**
AWS 리소스들을 정의한 파일이다.

```hcl
data "aws_ami" "al2023" {  
  most_recent = true  
  owners      = ["amazon"]  
  
 filter {  
    name   = "name"  
    values = ["al2023-ami-*-x86_64"]  
  }  
}
```
최신 Amazon Linux 2023 AMI를 검색하는 코드이다. 

‘data’ 키워드는 이미 존재하는 것 또는 AWS가 제공하는 조회 결과를 읽기 전용으로 가져오는 데이터 소스이다.

```hcl
resource "aws_vpc" "this" {  
  cidr_block           = var.vpc_cidr  
  enable_dns_support   = true  
  enable_dns_hostnames = true  
  
  tags = {  
    Name = "${var.project_name}-vpc"  
  }  
}
```
DNS 옵션을 활성화하여 VPC를 생성한다. 이유는 AWS에서 VPC 내부 통신 시 DNS를 사용하기 때문이다.

‘resource’ 키워드는 terraform이 생성, 수정, 삭제하는 인프라 객체이다.

```hcl
resource "aws_internet_gateway" "this" {  
  vpc_id = aws_vpc.this.id  
  
  tags = {  
    Name = "${var.project_name}-igw"  
  }  
}
```
VPC에 연결할 IGW를 생성한다.

```hcl
resource "aws_subnet" "public" {  
  vpc_id                  = aws_vpc.this.id  
  cidr_block              = var.public_subnet_cidr  
  availability_zone       = data.aws_availability_zones.available.names[0]  
  map_public_ip_on_launch = true  
  
  tags = {  
    Name = "${var.project_name}-public-subnet"  
  }  
}
```
‘map_public_ip_on_launch’ 설정을 참으로 설정하여 퍼블릭 서브넷을 생성한다. 

```hcl
resource "aws_route_table" "public" {  
  vpc_id = aws_vpc.this.id  
  
 route {  
    cidr_block = "0.0.0.0/0"  
    gateway_id = aws_internet_gateway.this.id  
  }  
  
  tags = {  
    Name = "${var.project_name}-public-rt"  
  }  
}
```  
VPC의 트래픽이 인터넷으로 나가는 기본 경로(IGW)가 설정된 라우트 테이블을 생성한다.

```hcl
resource "aws_route_table_association" "public" {  
  subnet_id      = aws_subnet.public.id  
  route_table_id = aws_route_table.public.id  
}
```  
퍼블릭 서브넷과 라우트 테이블을 연결한다.

```hcl
resource "aws_security_group" "ec2" {  
  name        = "${var.project_name}-sg"  
  description = "No inbound. Outbound allowed for updates + SSM."  
  vpc_id      = aws_vpc.this.id  
  
  egress {  
    from_port   = 0  
    to_port     = 0  
    protocol    = "-1"  
    cidr_blocks = ["0.0.0.0/0"]  
  }  
  
  tags = {  
    Name = "${var.project_name}-sg"  
  }  
}
```
EC2 용 Security Group을 생성한다. 인바운드 규칙이 없어 외부에서 들어오는 트래픽을 모두 차단한다. 반대로 아웃바운드 규칙은 모든 외부 통신을 허용한다.

```hcl
resource "aws_iam_role" "ec2_ssm_role" {  
  name = "${var.project_name}-ec2-ssm-role"  
  
  assume_role_policy = jsonencode({  
    Version = "2012-10-17",  
    Statement = [{  
      Effect    = "Allow",  
      Principal = { Service = "ec2.amazonaws.com" },  
      Action    = "sts:AssumeRole"  
    }]  
  })  
}
```
EC2가 IAM 권한 정책을 연결할 수 있는 Role을 생성한다.

```hcl
resource "aws_iam_role_policy_attachment" "ssm_core" {  
  role       = aws_iam_role.ec2_ssm_role.name  
  policy_arn = "arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore"  
}
```
SSM 사용이 가능하도록 ‘AmazonSSMManagedInstanceCore’ 정책을 EC2 Role에 부착한다.

```hcl
resource "aws_iam_instance_profile" "ec2_profile" {  
  name = "${var.project_name}-ec2-profile"  
  role = aws_iam_role.ec2_ssm_role.name  
}
```
EC2에 Role을 붙이기 위한 Instance Profile을 생성한다. Instance Profile은 EC2용 IAM Role 컨테이너이다. 콘솔을 사용하여 EC2에 Role을 부착할 때는 AWS에서 자동으로 Instance Profile을 생성하여 Role을 부착했다. terraform에서는 수동으로 정의해야 한다.

```hcl
resource "aws_instance" "this" {  
  ami                         = data.aws_ami.al2023.id  
  instance_type               = "t3.micro"  
  subnet_id                   = aws_subnet.public.id  
  vpc_security_group_ids      = [aws_security_group.ec2.id]  
  iam_instance_profile        = aws_iam_instance_profile.ec2_profile.name  
  associate_public_ip_address = true  
  
  user_data = <<-EOF  
              #!/bin/bash  
              dnf -y update | true  
              EOF  
  
  metadata_options {  
    http_tokens = "required" # IMDSv2 필수 (자격 증명 탈취 방지 강화)  
  }  
  
  tags = {  
    Name = "${var.project_name}-ec2"  
  }  
}
```
‘associate_public_ip_address’를 참으로하여 퍼블릭 IP를 활성화하고 SSM Role(Instance Profile)을 부착하여 EC2 인스턴스를 생성한다. IMDS(Instance Metadata Service)를 이용하여 인스턴스 메타데이터가 유출되는 것을 방지하기 위해 ‘http_tokens’를 “required”로 설정하여 취약점을 없앴다.

**output.tf**
```hcl
output "vpc_id" {  
  value = aws_vpc.this.id  
}  
output "instance_id" {  
  value = aws_instance.this.id  
}  
output "instance_public_ip" {  
  value = aws_instance.this.public_ip  
}
```
