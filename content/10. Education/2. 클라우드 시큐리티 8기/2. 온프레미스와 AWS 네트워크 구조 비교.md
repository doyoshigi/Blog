# 온프레미스와 AWS 네트워크 구조 비교
## AWS 인프라 구성
**리전(Region)**
- AWS 서비스가 제공되는 물리적인 서버 위치로 각 리전은 완전히 물리적으로 분리된 여러 데이터 센터(가용 영역)으로 구성된다. 
- 각 리전은 최소 2~3개 이상의 가용 영역을 포함하고, 서로 간 데이터와 서비스를 독립적으로 운영할 수 있다.
- 온프레미스에서 해외나 지방 등 지리적으로 분리된 데이터센터가 대응된다.
**가용 영역(Availability Zone, AZ)**
- 리전 내에 위치한 하나 이상의 데이터 센터 집합으로 각 AZ는 독립적으로 운영된다.
- 모든 AZ는 서로 100km 이내의 거리에 위치하지만, 일정 물리적 거리를 두어 자연재해 등에도 독립성을 가진다.
- AZ 간 데이터 동기화가 가능하고, 네트워크는 완전 중복 구조로 설계되어 있다
- 온프레미스에서 데이터 센터 내의 분리된 전산실/층 또는 근거리의 제2의 데이터센터로 대응된다.
**VPC(Virtual Private Cloud)**
- AWS 상에서 논리적으로 격리된 사용자 전용 가상 네트워크로 네트워크 구성을 자유롭게 정의할 수 있다.
- VPC는 리전 단위로 생성되며, 각 AZ에 하나 이상의 서브넷을 둘 수 있다.
- 온프레미스에서 하나의 데이터센터 전체의 네트워크로 대응된다.
**Subnet**
- VPC를 IP 주소 범위로 나눈 단위
- 온프레미스의 L2 스위치와 VLAN에 대응되는 개념이다.
- 온프레미스에서는 하나의 VLAN이 물리적 위치에 구애받지 않고 확장될 수 있지만, AWS에서는 고가용성, 재해 복구 측면을 고려해 하나의 Subnet이 하나의 AZ에 종속된다.

### Inbound Network Traffic Flow
**온프레미스 네트워크**에서 통신 시 **인바운드 트래픽**은 **인터넷 -> 데이터센터(전산실) 외부망 경계 -> L3 스위치 -> 방화벽 -> L4 스위치 -> L2 스위치 -> 서버** 순으로 이동한다. 
**AWS 네트워크**에서는 **인터넷 -> VPC 경계 -> IGW -> NACL -> AWS Network Firewall -> ELB  -> Security Group -> EC2** 순으로 이동한다.

| 온프레미스                           | AWS                                                               | 설명                                                                                       |
| ------------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 데이터센터 외부망 경계                    | VPC 경계                                                            | 외부망(인터넷)에서 내부 관리 영역으로 들어오는 첫 지점이다.                                                       |
| L3 스위치(라우터)                     | IGW(Internet Gateway) + Ingress Routing Table                     | 외부와 내부를 연결하고 Public IP를 Private IP로 반환하는 역할을 한다.(1:1 NAT)<br><br>트래픽이 가야 할 목적지 경로를 확인한다. |
| L3 스위치 ACL(Access Control List) | NACL(Network ACL)                                                 | 서브넷(VLAN)에 접속할 때 IP/Port를 기반으로 트래픽을 차단/허용한다.                                             |
| 방화벽                             | AWS Network Firewall                                              | 단순 IP 차단을 넘어, 패킷의 내용을 보고 바이러스나 해킹 공격을 탐지/차단한다.                                           |
| L4 / L7 스위치(로드밸런서)              | ELB(Elastic Load Balancing)<br><br>- NLB(L4)<br>    <br>- ALB(L7) | 트래픽을 여러 서버로 분산시켜 부하를 줄이고 고가용성을 확보한다.                                                     |
| L2 스위치 + VLAN                   | Subnet                                                            | 동일한 네트워크 대역 내의 리소스 간 통신을 연결한다.                                                           |
| 해당 없음                           | Security Group                                                    | 개별 서버 단위의 인바운드 트래픽을 허용/차단한다.                                                             |
| 서버                              | EC2                                                               | 실제 프로그램이 돌아가는 가상 컴퓨터이다.                                                                  |

### Outbound Network Traffic Flow
**온프레미스 네트워크**에서 통신 시 **아웃바운드 트래픽**은 **서버 -> L2 스위치 -> L3 스위치 -> 방화벽 -> 외부망 라우터(L3) -> 인터넷** 순으로 이동한다. 
**AWS 네트워크**에서는 **EC2 -> Security Group -> NACL -> NAT GW -> IGW -> 인터넷** 순으로 이동한다.

| 온프레미스           | AWS                  | 설명                                                  |
| --------------- | -------------------- | --------------------------------------------------- |
| 서버              | EC2                  | 실제 프로그램이 돌아가는 가상 컴퓨터이다.                             |
| 해당 없음           | Security Group       | 개별 서버 단위의 아웃바운드 트래픽을 허용/차단한다.                       |
| L2 스위치 + VLAN   | Subnet               | 동일한 네트워크 대역 내의 리소스 간 통신을 연결한다.                      |
| L3 스위치(게이트웨이)   | Route Table          | 인터넷으로 가려면 어디로 가야하는 지 트래픽이 가야 할 목적지 경로를 확인한다.        |
| L3 스위치 ACL      | NACL                 | 서브넷 경계(VLAN)를 빠져나갈 때 IP/Port 기반으로 트래픽을 차단/허용한다.     |
| 방화벽             | NAT GW               | Private IP를 Public IP로 변환한다.                        |
| 방화벽             | AWS Network Firewall | 패킷의 내용을 보고 정보 유출이나 악성 통신을 차단한다.(선택 사항)              |
| 외부망 라우터(L3 스위치) | IGW                  | 외부 인터넷 망과 연결되는 접점이다.<br><br>트래픽이 가야 할 목적지 경로를 확인한다. |
| 데이터센터 외부망 경계    | VPC 경계               | 내부망 영역을 벗어나 인터넷으로 나간다.                              |

# AWS 실습 환경 구성
![[Pasted image 20251207144101.png]]

인바운드, 아웃바운드 트래픽의 흐름은 아래와 같다
**Inbound Traffic**
- Internet → IGW → Route Table(Public Subnet)  →  NACL(Public Subnet) → Security Group(ALB) → ALB(Public Subnet) → Route Table(Private Subnet) → EC2 Server(Private Subnet)
**Outbound Traffic**
- EC2 Server(Private Subnet) → Security Group (Private EC2) → NACL(Private Subnet) → Route Table(Private Subnet) → Security Group (NAT Instance) → NAT Instance(EC2 with iptables, Public Subnet) → NACL (Public Subnet Outbound) → Route Table(Public Subnet) → IGW → Internet

## VPC 리소스 맵
![[Pasted image 20251207144202.png]]

Public Subnet과 Private Subnet을 분리하여 네트워크를 구성했다. Public Subnet에는 NAT 역할을 담당하는 EC2 인스턴스가, Private Subnet에는 웹서버 역할을 하는 EC2 인스턴스가 위치한다.
Public Subnet과 Private Subnet은 각각 CIDR 블록을 10.0.1.0/24, 10.0.2.0/24 대역을 할당받았다.

## 라우팅 테이블
### Public Subnet
![[Pasted image 20251207144918.png]]

Public Subnet에 연결된 라우팅 테이블은 트래픽을 IGW로 라우팅하도록 설정했다.

### Private Subnet
![[Pasted image 20251207145139.png]]

Private Subnet에 연결된 라우팅 테이블은 트래픽을 Public Subnet에 존재하는 NAT EC2 인스턴스로 라우팅하도록 설정했다.

## ELB
웹 서비스의 부하 분산과 외부 접속을 위해 Public Subnet에 ALB를 배치했다. ALB는 Private Subnet에 있는 EC2의 80번 포트로 트래픽을 전달한다. ALB를 추가하기 위해 같은 리전의 AZ에 별도의 Public Subnet을 생성했다.

## NAT EC2 인스턴스
EC2 인스턴스에서 리눅스 커널의  ip_forward를 활성화하여 패킷 포워딩을 허용하고 iptables의 MASQUERADE 설정을 통해 Source NAT을 구현했다. 그리고 AWS 콘솔에서 ‘소스’대상 확인 중지’ 설정을 적용했다.

### Outbound Traffic

Private Subnet의 EC2 인스턴스에서 “traceroute -n google.com” 명령어를 입력하여 출력된 결과이다. 1번 라인에 Public Subnet의 NAT EC2 인스턴스가 출력되는 것으로 보아 정상적으로 작동하는 것을 확인할 수 있다.
