## TCP(Transmission Control Protocol)
TCP는 트렌스포트 계층 프로토콜로, 애플리케이션에 신뢰성 있는 바이트 스트림 전송을 제공한다.

## 특징
**1. 연결 관리**
- 통신 전에 3-way handshake로 연결을 맺고, 통신이 끝나면 4-way handshake로 연결을 끊는다.

·**2. 신뢰성**
- TCP는 Sequence / ACK을 이용하여 전달 여부를 확인하고 손실 시 재전송한다.
	- **ACK:** 수신자가 다음에 받아야 하는 바이트 번호를 보내 수신 범위를 알려준다.
	- **재전송:** 타임아웃 또는 중복 ACK 반복 시 손실로 판단해 재전송한다.

**3. 순서 보장**
- Sequence Number로 바이트 스트림에 번호를 부여한다.
- 수신 측은 번호를 보고 세그먼트를 정렬할 수 있다.

**4. 전송률 조절**
- **흐름 제어(수신자 보호)**: 수신자가 처리할 수 있는 속도에 맞춰서 세그먼트를 전송한다.(수신 버퍼가 넘치지 않게 조절)
- **혼잡 제어(네트워크 보호):** 네트워크(중간 경로)가 혼잡한지를 확인하고 전송한다. 혼잡하면 전송량을 줄이고, 괜찮다면 늘리는 방식으로 조절한다.

## 3-way handshaking(연결 수립)
서로 통신의사를 확인하고 초기 시퀀스 번호를 동기화하기 위해 3-way handshaking을 진행한다. 연결이 수립되어 양쪽에 TCP 연결 상태를 생성한다.

![[Pasted image 20251227201048.png]]

**흐름**
1. 클라이언트가 SYNbit=1, seq=x을 서버에 전송한다.
2. 서버는 이에 응답하여 SYNbit=1, seq=y, ACKbit=1, ACKnum=x+1로 응답한다.
3. 클라이언트는 ACKbit=1, ACKnum=y+1로 응답하고 이를 서버가 수신하면 연결이 수립된다.

## 4-way handshaking(연결 종료)
연결을 종료하기 위해 4-way handshaking을 진행한다.

![[Pasted image 20251227201213.png]]

**흐름**
1. 연결을 종료하고 싶어하는 클라이언트가 FINbit=1, seq=x 세그먼트를 서버에 전송한다.
2. 서버는 ACKbit=1, ACKnum=x+1로 응답한다.
3. 서버는 FINbit=1, seq=y 세그먼트를 클라이언트에게 전송한다.
4. 클라이언트는 ACKbit=1, ACKnum=y+1로 응답한다.
	- 이때 서버가 ACK 요청을 받을 때까지 잠시 기다린다. 
		- ACK 세그먼트가 유실될 가능성이 있으며 ACK 세그먼트가 새 연결에 들어와서 새 데이터처럼 처리될 가능성이 있기 때문이다.

## 헤더 구조
![[Pasted image 20251227190433.png]]

TCP의 헤더는 20Byte의 크기를 가지며 옵션을 포함하면 최대 60Byte까지 늘어날 수 있다.

- **Source/Destination Port:** 어떤 프로세스로 보내는지 구분한다. (포트 기반 다중화)
- **Sequence Number:** 이 세그먼트 데이터가 바이트 스트림에서 어디 위치인지를 표시한다.
	- **순서 재조립, 중복 제거, 손실 감지**
- **Aknowledgement Number:** 수신자가 다음에 받고 싶은 바이트 번호를 표시
	- 전달 확인, 재전송 판단
- **Flag(제어 비트)**
	-  **URG:** TCP 헤더의 Urgent Pointer 필드 유효
	- **SYN:** 연결 시작
	- **ACK:** Acknowledgment Number가 유효
	- **PSH:** 수신 측 버퍼에 더 쌓아두지 말고 애플리케이션에 빨리 전달하라는 뜻
	- **FIN:** 정상 종료
	- **RST:** 연결을 즉기 리셋/강제 종료할 때 사용
- **Window Size:** 수신 버퍼의 여유 공간
- **Checksum:** 전송 중 오류 검출
-  **Options**
	- **MSS:** 최대 세그먼트 크기
	- **Window Scale:** 16비트 Window 한계를 넘기 위해 윈도우 확장에 사용
	- **SACK:** 데이터 손실 시 이미 받은 구간을 표시하여 불필요한 재전송 줄이기


**RST 플레그**
- 공격자가 포트 스캐닝/서비스 탐색을 위해 사용한다.
	- 스캔 대응 포트가 닫혀 있으면 서버가 RST로 연결 안됨을 돌려준다.
- 리셋 주입
	- 위조 RST를 보내서 연결을 강제로 끊게 만들 수 있다.

**TCP 구조적 취약점**
- TCP는 연결 지향이기 때문에 서버가 연결마다 상태를 유지해야 해서 연결 고갈 공격에 취약하다.
	- SYN 플러딩: 서버에 SYN만 대량으로 보내 서버의 half-open 연결 큐를 채워 정상 연결을 못 받게 만드는 공격이다.
	- 연결 수 고갈: 연결을 대량으로 수립하여 연결 한도가 고갈되게 만들어 정상 연결을 못받게 만드는 공격이다.
	- 데이터를 아주 느리게 보내 연결을 오래 붙잡아 자원을 소모시키는 방법도 있다.
