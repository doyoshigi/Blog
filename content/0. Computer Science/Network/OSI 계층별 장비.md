## 물리 계층
- 비트를 전기/광/무선 신호로 변경하여 전송

**케이블(Cable)**
- 전기/광/무선 신호로 비트를 물리적으로 전송한다.

**리피터(Repeater)**
- 약해진 물리 신호를 재생, 증폭하여 전송 거리를 늘린다.

**허브(Hub, L1)**
- 멀티포트 리피터로, 들어온 신호를 재생성하여 모든 포트로 전송한다.
- 목적지 구분을 못하므로 트래픽이 많아지면 충돌이 증가한다.
- 허브에 연결된 전체가 하나의 충돌 도메인(Collision Domain)이 된다.

>[!note] 충돌 도메인(Collision Domain)  
>동시에 전송된 신호가 같은 매체에서 겹쳐 충돌이 발생할 수 있는 범위.

## 데이터 링크 계층
- MAC 주소를 기반으로 동일한 LAN에서 데이터 전송 담당, 오류 검출

**브릿지(Bridge)**
- LAN 세그먼트들을 연결하는 장비로, 프레임 단위로 동작한다.
- MAC 주소를 학습하여 필요한 포트로만 프레임을 포워딩한다.
	- 들어오는 프레임의 Source MAC을 보고 MAC 테이블을 학습하고, Destination MAC이 테이블에 있으면 해당 포트로만 포워딩 한다.
	- Destination MAC을 모르면 unknown unicast 플러딩, 브로드캐스트/멀티캐스트는 플러딩한다.
- 충돌 도메인은 분리하지만, 브로드캐스트 도메인은 분리하지 않는다.

>[!note] 플러딩(Flooding)  
> 브릿지/스위치가 프레임의 목적지를 모르거나, 브로드캐스트/멀티캐스트일 때 프레임을 복사해서 여러 포트로 보내는 포워딩 동작을 말한다.(들어온 포트는 제외)
>

**스위치(Swtich, L2)**
-  멀티포트 브릿지로 MAC 주소 기반으로 프레임을 필요한 포트로만 전달한다.
-  MAC주소 학습을 통해 포워딩한다.
	- 프레임이 들어오면 Source MAC과 들어온 Port로 테이븡르 학습/갱신한다.
	- Destination MAC이 테이블에 있으면 해당 포트로만 유니캐스트 포워딩한다.
		- 없으면 Unknown Unicast 플러딩을 한다.(들어온 포트를 제외한 같은 VLAN의 모든 포트로 전송)
	- 브로드캐스트는 같은 VLAN 전체로 플러딩한다.
- 충돌 도메인은 포트 단위로 분리한다.
- 포트별로 충돌 도메인이 분리한다. 브로드캐스트 도메인은 VLAN 단위로 나뉜다.
- VLAN을 통해 브로드캐스트 도메인을 분리할 수 있다.
	- Access 포트: 하나의 VLAN에만 소속
	- Trunk 포트: 여러 VLAN 트래픽을 태그로 구분해 한 링크로 전달

> [!note] VLAN(Virtual LAN)
> VLAN은 하나의 물리 스위치/배선을 논리적으로 여러 개의 LAN으로 쪼개는 기술이다.

**브릿지와 스위치의 비교**
- 공통점
	- 둘다 L2에서 프레임 단위로 MAC 주소를 학습하여 포워딩한다.
	- 충돌 도메인을 포트 단위로 분리하고 브로드캐스트 도메인은 유지한다.(VLAN 사용 x)
- 차이점
	- 브릿지는 포트 수가 적고 성능이 낮다(소프트웨어 기반). 스위치는 포트 수가 많고 성능이 높다(하드웨어 기반).
	- 스위치는 Store-and-Forward, Cut-Through 방식을 사용하지만 브릿지는 Store-and-Forward 방식만 사용할 수 있다.

> [!note] Store-and-Forward, Cut-Through
> **Store-and-Forward:** 프레임 전체를 받은 후 오류를 검출하고 정상일 때만 전달
> **Cut-Through:** 프레임의 목적지 주소만 보고 전송 처리를 시작

## 네트워크 계층
IP 주소 기반으로 라우팅/포워딩하여 네트워크 간 패킷을 전달한다.

**라우터(Router, L3)**
- 서로 다른 네트워크(브로드캐스트 도메인/서브넷)를 연결한다.
- 목적지 IP 주소를 보고 라우팅 테이블에 따라 다음 홉/출력 인터페이스를 결정한다.
- 포워딩 시 TTL(Time To Live)을 감소시키고, 출력 시에는 다음 홉의 MAC을 ARP로 해석해 L2 프레임으로 전송한다.
- NAT/ACL/QoS 같은 기능이 함께 들어가기도 한다.

**L3 스위치**
- L2 스위칭 + L3 라우팅을 수행한다.
- IP 헤더를 보고 L3 포워딩을 하며, 보통 LAN 내부에서 고속 처리를 담당한다.

> [!note] 정적 라우팅, 동적 라우팅
> 라우팅의 종류에는 정적, 동적 라우팅이 있다.
> 
> **정적 라우팅(Static Routing)**
> 	관리자가 직접 경로를 수동으로 설정하는 방식이다.
> 	장점: 단순하기 때문에 오버헤드가 거의 없다.
> 	단점: 네트워크가 커지면 관리가 힘들고, 링크 장애 시 자동 우회가 안된다.
> 
> **동적 라우팅(Dynamic Routing)**
> 	라우터들이 라우팅 프로토콜로 서로 경로 정보를 교환해서 테이블을 자동으로 만드는 방식이다.
> 	장점: 규모가 커도 관리가 쉽고, 장애 발생 시 자동으로 경로 후회가 가능하다.
> 	단점: 설정/운영이 복잡, 라우팅 업데이트 오버헤드가 존재한다.
> 
> **보안 관점**
> 정적 라우팅: 라우팅 테이블이 노출되었을 때 중간 경로가 노출된다.
> 동적 라우팅: 라우팅 테이블이 노출되었을 때 중간 경로가 노출되지 않는다.
> 동적 라우팅이 라우팅 정보 교환이 있어 보호가 약하면 공격 표면이 커질 수 있다.

## 트렌스포트 계층
종단간 데이터 전송, 포트 기반 다중화를 담당

**L4 로드 밸런서(Load Balancer)**
- IP/포트/프로토콜 등 L4 정보 기준으로 트래픽을 분산한다.
- Virtual IP 기반으로 서버 풀로 전달하며, NAT 형태로 연결을 중개한다.
- 장비에 따라 헬스체크, 세션 유지 기능을 포함할 수 있다.

**방화벽(Firewall)**
- 네트워크 경계에서 트래픽을 정책에 따라 허용/차단하는 접근 제어 장비이다.
- 전통적 방화벽은 주로 L3/L4 정보(IP/프로토콜/포트) 기반으로 필터링하며, Stateful inspection으로 연결 상태를 추적해 정상 세션의 응답 트래픽을 허용하는 방식으로 동작한다.
- NGFW(Next-Generation Firewall) 여기에 더해 DPI(Deep Packet Inspection)로 패킷 내용을 분석하고 애플리케이션 계층 단위까지 정책을 적용할 수 있다.

## 애플리케이션 계층
사용자/애플리케이션 수준의 네트워크 서비스 제공

**WAF(Web Application Firewall) / 프록시**
- WAF: HTTP(S) 트래픽에서 웹 공격 패턴(SQLi, XSS 등)을 탐지/차단한다.
- 프록시: 중계하면서 캐싱/인증/로깅/접근제어 등 정책을 수행할 수 있다.
