## OSI 모델이란?
OSI(Open Systems Interconnection) 모델이란 네트워크 통신을 위해 필요한 기능을 7개의 계층으로 추상화한 참조 모델(Reference Model)이다. 

과거에는 네트워크 장비 회사마다 사용하는 프로토콜이 달라서 사용하는 장비의 회사가 다르면 서로 통신할 수 없었다. 이를 해결하기 위해 ISO에서 표준적인 네트워크 통신 모델인 OSI 모델을 만들었다.

## 계층화의 장점
1. 유지보수/수정 시 편리하다. 
	- 각 계층은 독립적이기 때문에 하나의 계층을 수정할 때 다른 계층은 신경쓰지 않아도 된다. 
2. 추상화를 통해 네트워크 이해가 편하다. 
	- 7개의 기능으로 추상화하여 복잡한 네트워크를 이해하기 쉽게 만들었다.
3. 트러블 슈팅 시 편리하다.
	- 문제가 발생하면 하나의 계층으로 원인을 좁히고 다른 계층은 신경쓰지 않고 조사할 수 있다.

## 7계층
![[Pasted image 20251223235231.png]]

**7. 애플리케이션 계층**
사용자/애플리케이션 수준의 네트워크 서비스를 담당합니다.

**6. 프레젠테이션 계층**
데이터 표현의 변환을 담당합니다.(암호화/인코딩/압축)

**5. 세션 계층**
세션의 시작/지속/종료와 동기화를 담당합니다.

**4. 트렌스포트 계층**
종간단 세그먼트/데이터그램의 전송, 포트 기반 다중화를 담당합니다.

**3. 네트워크 계층**
IP 주소 기반 라우팅/포워딩으로 네트워크 간 패킷을 전달한다.

**2. 데이터 링크 계층**
MAC 주소를 기반으로 같은 LAN에서 프레임 전송과 오류 검출을 담당합니다.

**1. 물리 계층**
비트를 전기/광/무선 신호로 변환하고 전송합니다.

## 캡슐화/역캡슐화
![[Pasted image 20251227165424.png]]

캡슐화는 데이터 송신 시, 데이터가 각 계층을 이동할 때 각 계층이 자신의 기능 수행에 필요한 헤더를 붙여서 하위 계층으로 전달하는 것이다.
반대로 역캡슐화는 데이터 수신 시, 각 계층이 헤더를 검증, 처리한 후 제거하여 상위 계층으로 전달하는 것이다.

**헤더를 붙이는 이유**
헤더를 붙이는 이유는 주소, 포트, 오류검출 같은 계층별 제어정보가 필요하기 때문이다.

## TCP/IP 모델
![[Pasted image 20251227174251.png]]

TCP/IP 모델은 인터넷에서 실제로 사용되는 통신 방식을 계층으로 나눈 모델이다.

TCP/IP 모델의 각 계층을 OSI 참조 모델과 비교하면 아래와 같다.
**애플리케이션 계층**
- OSI 참조 모델의 애플리케이션, 프레젠테이션, 세션 계층

**트렌스포트 계층**
- OSI 참조 모델의 트렌스포트 계층

**인터넷 계층**
- OSI 참조 모델의 네트워크 계층

**네트워크 인터페이스 계층**
- OSI 참조 모델의 데이터 링크, 물리 계층
